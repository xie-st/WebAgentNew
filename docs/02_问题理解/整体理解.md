# 赛题整体理解

更新：2026-10-30，依据[比赛要求汇总](../比赛要求/WebAgent比赛要求.md)。

## 任务

让 Web Agent 稳定、快速地完成网页任务。验收分为 **10 个论坛／电商模拟环境用例＋1 个公开真实网站用例**：前者由官方程序校验，后者视频连线查验真实交互、并行、限流与人工衔接。

## 限制与要求

- 验收主模型固定为 **Qwen3.6-35B-A3B**；轻量辅助模型须报备。自动化平台统一调用模型，选手提交 messages，不配置模型或推理参数。
- Agent 本地开发，主动连接赛方平台；开发语言与框架不限。当前自动化接口为可访问性树文本、元素编号与单请求单动作。
- **每队同时只运行一个评测任务**；自动化评测网站按单请求单动作执行，不支持多 Tab，不开放 curl 或 JS 注入。截图后续可以提供，当前 snapshot 不等于截图接口已开放。真实网站用例实现和展示 Tab 切换、并行操控及用户接管，进阶方案可在该场景验证。
- 遵守限流和任务时限；禁止绕过网页改数据、预写答案、日志造假及违规外部模型／API／算力调用。
- 日志保留操作时间、目标页面、动作类型、结果、模型调用量；一队一账号，验收按账号查验。
- 提交可运行工程和原题要求的 3–5 页报告，配合视频验收与复测答辩。调测成绩不计最终成绩。

## 评价指标

原题权重：成功率与鲁棒性 45%，完成时间 20%，操控质量 15%，成本 10%，报告 10%；新说明未调整权重。

通过率至少 60% 才能排名；单用例无部分分。计时从指令下发到验收检查，扣除人工介入；原题时间分按已通过任务总耗时排名。真实网站用例如何计入通过率与分数仍待明确。

## 执行流程

1. **任务规划**：明确目标、先后顺序和完成条件，根据进展调整计划。
2. **页面观察与提取**：看懂页面，找到要操作的对象和需要的信息。
3. **网页行动**：执行网页操作，获取反馈，跟踪页面变化。
4. **结果检验**：选择合适的时机和方法检查结果，及时发现错误。
5. **失败处理**：分清操作失败还是结果不明，保留已完成的工作，决定重试、恢复或停止。
6. **人工接管**：遇到登录或验证时暂停并提示用户，完成后继续执行。

## 优化方向

1. **并发调度**：在真实网站用例中安排可同时执行的步骤，处理依赖、共享状态和网站限流。
2. **限流控制**：控制访问频率和并发数量，遇到限流时等待或降低频率，避免触发网站封禁。
3. **行动效率**：复用可靠的操作逻辑，减少多余操作和重复观察。
4. **模型调用效率**：在模型和推理设置固定的条件下，优化调用时机、输入内容和输出长度。
5. **上下文管理**：记录任务状态、必要历史和当前进度。
6. **提示词优化**：写清目标、规则和输出要求，在关键步骤通过钩子补充提示、检查和恢复条件。
7. **Skill**：把常用流程整理成技能，写清何时用、怎么做、怎么检查，在需要时加载使用。

## 评估维度

- **成功率与鲁棒性**：完整通过比例，异常下保持完成和恢复的能力。
- **时间**：通过任务耗时、人工介入扣除、并行相对串行的收益。
- **成本**：页面访问、模型调用与 token 消耗。
- **交互衔接**：真实网站用户接管、恢复与限流表现。

## 待研究

- 固定模型下，哪些决策交给模型，哪些交给程序？如何复用经验与优化策略参数？
- 官方 baseline 的主要失败点与耗时在哪里？框架中的规划、检验、恢复模块如何迁入平台接口？
- 真实网站如何接统一模型并实现接管与并行；自动化平台截图何时开放、如何接入？
- 最终时限、真实网站计分、辅助模型报备和工程提交细则。

当前调测按接入指南可执行整批任务；300 秒是该指南的平台细则，未被确认为最终验收统一时限。以上优化项保留为研究提纲，尚未实现。
