# 观察、效率与并行核查

日期：2026-10-30。用途：将 RoadMap 中四条研究路线转成阶段方案依据。以下工程安排均为候选，未审批、未实现。

## 综合判断

Prune4Web 解决长 DOM 下的候选定位；UI-TARS 研究视觉输入到动作的原生模型；WebClipper 用裁剪后的检索轨迹继续训练；Flash-Searcher 用动态依赖图组织并行检索。它们分别涉及观察、模型能力、离线学习和运行调度，不能合称为可直接接入的四个插件。

本项目固定比赛模型，因此优先借鉴程序评分、动作与观察关联、轨迹依赖分析、依赖感知调度。训练所得能力与原文收益不记为本项目已有能力。

## Prune4Web：由模型确定筛选线索，由程序遍历元素

作者看到的问题是完整 DOM 太长，简单截断会丢失目标，另用模型逐元素排名又没有解除长输入负担。其判断是让模型从子任务生成关键词与权重，由固定评分函数遍历页面元素，最后让 Grounder 在候选中定位。这比不受约束地生成任意过滤代码更容易控制。

原方法还包括交互性、可见性与层级预处理，及 Planner／Filter／Grounder 的联合训练。低层定位评测使用给定的正确子任务，不能将其定位准确率当成端到端任务完成率。实验支撑评分：8/10，支持其程序筛选与定位的核心故事。

本项目适配：保留完整的原始观察，提供候选筛选开关；筛选结果保留原始元素编号、来源观察与必要文本。候选不足时允许扩大范围或回到原始观察。只有当前观察中有效的元素才能成为动作目标，不能把 DOM 节点 ID 自动视作平台 AX 动作 ID。

官方端仅在新版 SDK 明确提供的 HTML／DOM 上做本地处理，不照搬浏览器 JS 注入或事件派发。真实端也须通过实际浏览器渲染与动作完成任务。关键词和评分参数的生成成本计入总调用与 token 消耗。

证据：[本地材料](论文/01_Prune4Web.md) §1–4、附录 A.1–A.4、E.3。已读上述方法、实验与相关实现文本；未逐项阅读全部训练超参数、附录案例和代码清单。[一手页面](https://arxiv.org/abs/2511.21398)核对为 v1，2025-11-26。

## UI-TARS：截图能力来自训练，截图留证与截图理解分开

作者希望将感知、定位、推理与动作统一到一个模型，避免模块之间传递信息时失配。其核心工作包括大规模 GUI 感知数据、统一动作空间、推理轨迹增强、在线轨迹收集与纠错训练。截图是模型输入，而非附加到文本 Agent 上就自然生效的工具。

值得借鉴的是统一动作语义、明确完成与请求人工介入的动作，以及通过动作后的新观察纠正执行。论文还区分单步定位、离线动作预测与在线整任务评价；本项目验收也应分清接口正确与任务完成。

实验支撑评分：8/10，支持原生视觉 Agent 的核心故事。

本项目适配：第一阶段建立截图保存与对应页面／动作的证据关联；第二阶段接入暂停、接管和恢复，并重新获取页面状态。统一模型的图片输入能力须以实际接入协议确认，不能从“能下载 PNG”推导出“模型能看 PNG”。截图理解如涉及辅助模型，另按比赛要求处理；本轮不配置。

证据：[本地材料](论文/02_UI-TARS.md) 摘要、§1、§2.2、§3.2、§4.1–4.6、§5.4–5.5、附录 A／B 的文本说明。已覆盖上述方法与在线评价关键段落，§5.1–5.3 的全部表格、图像案例未逐项核查；不声称全文逐字读完。[一手页面](https://arxiv.org/abs/2501.12326)核对为2025-01-21提交。

## WebClipper：离线提取必要依赖，再训练高效行为

作者关注检索 Agent 在成功前反复搜索和探索无效分支的问题。其方法将行动与获得的信息分成两类节点，建立依赖图，提取近似最小必要 DAG，再改写被剪断的推理衔接，用所得轨迹继续训练。研究判断的重点是保留必要依赖，而不是凭轨迹长短删除步骤。

实验支撑评分：8/10，支持结构化裁剪与训练改善检索效率的核心故事。

本项目适配：先用于实验后的离线诊断，识别重复访问、没有贡献的分支，以及真正支撑结果的证据。将来提炼程序或 skill 时，须用新任务重放验证。浏览器动作还可能建立登录、页面、焦点或草稿状态，不能因为某步没产出新文本就删除；离线回看得到的必要路径也不能当作在线 Agent 预知的路径。

原始审计日志继续完整保存，分析副本可以标注冗余。裁剪分析不改写实际发生的历史。F-AE 是论文的研究指标，本项目仍按赛题完成率、时间、操作质量和成本评价。

证据：[本地材料](论文/03_WebClipper.md) §1–3.6 的关键方法、§4–5、附录 B.1–B.3、C.1–C.2；训练表格与所有改写示例未逐项核查。[一手页面](https://arxiv.org/abs/2602.12852)核对为 v2，2026-05-08。

## Flash-Searcher：动态 DAG 提供调度思想

作者把复杂检索拆成有依赖的分支，并根据中间结果调整执行图。其设计不完全等同于严格拓扑调度：还允许部分依赖未满足时先执行可提供验证信号的工作。研究中的工具主要是搜索与内容抓取，框架推理与轨迹蒸馏训练是两条路线。

对“DAG 并行本身造成多少效率收益”的实验支撑评分：7/10。关键缺口是效率对照保留了其他框架的原始配置，骨干模型与工具组合不同；已读材料未把同模型、同工具下的调度机制贡献单独隔离。步骤减少与多工具合批也不能直接换算成等比例的浏览器墙钟时间收益。

本项目适配：先使用明确依赖的就绪队列；真实网站可将无共享写冲突的页面工作分开执行。为每个执行分支保存 Tab、观察版本、输入和输出证据；共享登录态、业务对象或写目标时明确协调。计划变化后重查就绪条件，旧计划产生的过期结果不得直接覆盖当前状态。

浏览器状态隔离、写入冲突协调、限流与取消规则属于本项目新增工程要求。初始实现不启用依赖尚未满足的推测性写操作。自动化平台维持其单动作与并发限制，真实端的调度图可串行运行，便于同任务、同模型下比较串并行收益。

证据：[本地材料](论文/04_Flash-Searcher.md) §1–4.1、§4.2 的训练设定、§5–6、附录 A／B、C.1、E、G 与 H 的目录状态。附录 H 在本地只保留提示词标题，未据此声称已读其具体提示词；其余训练与案例未全面核查。[一手页面](https://arxiv.org/abs/2509.25301)核对为 v1，2025-09-29；本地正文另有2026-08-24日期，保留区别，不据此推断新 arXiv 版本。
