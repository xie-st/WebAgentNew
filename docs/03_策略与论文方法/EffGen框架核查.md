# EffGen 框架核查

日期：2026-10-30。依据：[论文原文](https://arxiv.org/html/2602.00887)、保存的 HTML／提取文本，以及 `code/effGen` 源码。

论文 v2（2026-06-14）描述的框架版本为0.2.10；本地源码为1.3.0、提交 `37de05a6b4ed01c90ee38b9c254a162927ca2ac2`。接口以当前源码为准。

论文从小模型的指令理解、工具调用和上下文约束出发，组合提示词优化、执行前复杂度判断、任务拆解与分层记忆。核心判断是按任务需要使用这些机制，避免每项任务都承担完整编排开销。实验支撑评分：8/10，支持该核心故事。

已读正文的方法与实验，补查附录 H 的记忆维护和 I.1 的工具契约。原文保存于 `论文/原文/EffGen_2602.00887.html`，提取文本便于检索。其余附录、作者连续研究尚未全面阅读；提取文本含公式重复，不作为代码来源。

对本项目的处理：保留 EffGen 主循环、工具注册与反馈机制；通过模型适配器连接官方文本接口，通过网页工具连接两套环境。先在单 Agent 配置下跑通，再逐项启用拆解、记忆与并行。论文的模型大小分类不直接决定比赛 MoE 模型的配置，提示词截断也不能删除任务条件或当前有效元素。

此前源码核查已确认：现有生成器用于输出执行事件，网页工具仍在内部直接运行。接入需要补充动作交出与观察返回的执行接口，并处理取消、超时与任务清理；不能只监听一个工具事件便认定网页动作完成。

官方模型调用受任务上下文约束，消息仅支持文本。适配时显式关闭不适用的能力探测、多模型路由与额外外部调用，保留可配置的任务内状态。具体配置与改动位置在第一阶段实施文档中列明。

下一步可编写第一阶段审批材料：目标、双环境接口、源码改动、DSH 分工与验收。框架论文与连接器核查已提供本阶段所需依据；尚未修改 EffGen 源码或运行模型。
