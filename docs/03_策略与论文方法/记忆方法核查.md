# 记忆方法核查

日期：2026-10-30。归属：RoadMap 实施前的论文依据。下文的阶段安排与接口含义是方案候选，尚未审批或实施。

## 综合判断

三种方法分别解决不同问题：M² 将历史交互压成短摘要，并检索跨任务经验；AgentProg 根据任务程序的控制流折叠历史、通过变量保留后续所需数据；《Read More, Think More》保留当前观察，并用差分减少旧观察的重复输入。不能将它们一并称为“程序侧折叠”，也不能一次叠加后将收益归给某一篇论文。

对本项目，优先理清“任务要求、已知事实、动作记录、完成证据”的关系，再决定哪些内容送入上下文。压缩历史时，仍被后续步骤依赖的对象值与完成证据必须有独立的保存位置。

## M²

作者针对的是长任务中历史观察不断膨胀、Agent 又反复踩同类导航陷阱的问题。设计将任务内轨迹压缩与跨任务经验指导分开：前者在行动同轮生成简短状态／动作摘要，后者从成功轨迹中提炼规则，并按任务语义检索。关键判断是让记忆服务下一步执行，而不把所有历史都作为同等重要的上下文。

原文的内部记忆是追加的摘要链，不是执行树，也不是固定大小的状态账本。“不另调摘要模型”不等于摘要没有输出 token 成本；“无需训练”也不等于经验库无需构建。原文经验库来自约55k条成功轨迹，使用独立模型提炼及句向量检索。

本项目可借鉴同轮摘要和“经验须与当前观察核对”。摘要应描述当前已观察状态和拟执行动作；动作的实际结果要等下一次观察核实，不能把行动意图写成已完成事实。后者是本项目的适配要求，而非对论文实现的直接转录。

实验支撑评分：8/10，支持其双记忆设计的核心故事。

证据位置：[本地全文](论文/07_M2-DualMemory.md) §2.2（同轮生成与追加摘要）、§2.3（经验提炼、检索与核对）、§3／表2–4（组件比较、成本与消融）、附录 A–F（相关工作、环境、经验示例与提示词说明）。已读取本地正文与附录文本；提示词图示本体未作逐字转录。网上核对版本为 [arXiv:2603.00503v1](https://arxiv.org/html/2603.00503v1)。

## AgentProg

作者看到的是：长任务既要丢弃已经结束的局部过程，又要保留以后仍要用的数据，普通滑窗或摘要缺少判断相关性的结构。其研究判断是用程序结构表达任务逻辑，以执行路径决定历史的存续，以变量跨步骤传递数据。程序指令保留自然语言语义，具体界面动作在运行时生成。

其核心不是先写死全部网页步骤。STP 给出控制流和数据依赖，模型根据当前观察生成动作并更新程序计数器；全局信念状态负责检查执行假设与真实环境是否一致。折叠后的历史仍可按程序步骤 ID 找回以往执行结果。

本项目可借鉴三点：按子目标／对象组织已完成过程；把后续所需值与历史叙述分开保存；发现状态冲突时修正受影响的状态，再恢复执行。这些机制可以由 EffGen 使用的外围状态与上下文工具提供，不能先验地把 AgentProg 的整套解释器另放在 EffGen 上层。

实验支撑评分：8/10，支持程序结构与信念状态帮助长任务执行的核心故事。

证据位置：[本地转录](论文/08_AgentProg.md) §2（问题与相关工作）、§3.1–3.4（STP、执行树、变量、信念状态）、§5.1–5.3（配置、组件消融和成本口径）、§6（定位）、附录 A–C。原实现采用规划模型与定位模型，动作生成和程序计数器更新交替进行；减少动态上下文并不自动代表总调用更少、总耗时更短。阶段方案应保留程序结构思想与完整复现之间的区别。

本地转录在附录 D 的 `Mode: Action` 处截断，缺少后续流程及附录 E。已到 [arXiv:2512.10371v2](https://arxiv.org/html/2512.10371v2) 补查附录 D 的变量／计数器示例与附录 E 的关键执行契约：观察优先、事实与假设区分、异常后恢复、内部计算与环境动作分开。未将本地转录标记为完整原文，也未将论文提示词当成本项目指令。

## 阶段划分候选

| 阶段 | 本轮核查给出的候选内容 | 验收要回答的问题 |
| --- | --- | --- |
| 第一阶段：双环境跑通 | 保存原始观察、发出动作、后续反馈及其关联；统一任务与页面／观察标识 | 每个动作是否确实交给环境，下一次观察是否接回同一循环；日志是否区分发出与确认 |
| 第二阶段：基础能力与测试环境 | 状态账本、关键值与证据引用、子目标进度；为摘要和折叠提供开关 | 切页、暂停恢复及上下文变化后，必要数据与完成状态是否仍可核对 |
| 第三阶段：逐批实验 | 同轮摘要、旧观察差分、按子目标折叠、经验检索分别验证 | 每次只改一个机制，并比较完整完成率、耗时、调用／token 成本与重复动作 |

拟采用的完成状态至少应区分“待执行、已发出待确认、已确认、结果不明／失败”。具体字段与状态转换待结合其余论文及 SDK 确定；本轮不定稿数据结构。
