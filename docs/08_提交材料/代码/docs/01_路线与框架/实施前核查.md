## EffGen 与平台的衔接

RoadMap 的目标是保留 EffGen 的观察、决策、执行和反馈循环，让外围适配环境。当前源码与这个目标相符，但现有生成器不能直接接收平台观察。

- `effgen/core/agent_react.py:92` 的 `_run_single_agent()` 通过 `run_to_completion(drive(...))` 驱动循环。
- `effgen/core/agent_loop.py:3360` 的 `drive()` 本身是生成器，当前标注为 `Generator[Any, None, AgentResponse]`；其 yield 用于 emitter 输出，不是已实现的网页动作／观察交换协议。
- 同文件 `2605`、`3160` 行分别在批量和单工具路径直接调用 `_execute_tool()`。网页工具暂停与恢复必须覆盖实际执行入口，不能只转发流式 `tool_call` 事件。
- `effgen/core/agent_tool_execution.py` 的工具执行含参数映射、错误处理、熔断、fallback 和结果归一化。抛异常退出循环再重新 `run()` 会丢失当前栈位置，不能当作生成器恢复。

方案比较：优先研究在现有循环上增加显式工具执行交换点，保留规划、工具记录和反馈路径；另起线程等待平台观察需要额外处理超时、取消和模型 contextvars；每步重新运行 Agent 则改变了原定连续循环。当前只确认优先核查方向，尚未确定补丁接口或实现方式。

`AgentConfig` 当前默认 `max_iterations=10`、`enable_sub_agents=True`、`enable_memory=True`、`capability_probe=True`，并支持 fallback 与多模型路由。平台基线必须显式配置，不能把默认值直接带进比赛；尤其不能把默认迭代上限当成平台步数限制。是否关闭某项及如何保留任务内状态，须在阶段方案中写清。

## 本地官方连接器

核查对象是 `code/webarena-outbound-client.zip`，SHA-256：`6eee7ddab6264aa228c29fce8ee0aff75f8e10067b65afcce9d5377dcdce496f`。

ZIP 共12个文件，没有 `third_party_agent/browser.py`；README 描述仅 AX 文本，不含截图或完整 DOM。因此当前本地包早于资料中的截图更新与最新 HTML／DOM 公告。不得把公告中的能力视为本地已接通，也不能从 baseline 提示词出现 `tab_focus` 就认定平台支持多 Tab。阶段接口必须以更新后的官方包和服务能力为准。

已直接核对包内 `my_agent.py`、`agent_logic.py`、`model.py`、`session.py`、`outbound.py`：

- 每项任务使用独立 spawn 子进程，Agent 对象在该任务的 reset／step 间存续，close 清理；任务内可保留生成器，不能依赖它跨进程重启存活。
- reset 未必有完整任务，完整任务从 step 获取；一次 step 仅返回一个动作。
- `model.generate(messages)` 依赖当前回调的 contextvars 绑定。只支持文本消息，返回 text 与 request_id；无供应商 token usage 字段。不得填造精确 token 数或费用，应记录本地调用数、request_id，平台 usage 另行关联。
- README 明确每任务最多一个模型调用同时执行；自建线程必须显式传播 contextvars。官方串行执行与真实网站多页面并行须分开配置。
- 模型重试、计算和网页操作共用任务预算。动作交出后，只有后续观察才能成为结果依据；不能在本地先记成功。

本轮没有解压覆盖 SDK、读取连接令牌或 env、启动客户端或发起评测。

## 论文阅读记录

首次核查已按上级《研究评估指导.md》读取 `10_ReadMoreThinkMore.md` 全文，包括实验、相关工作和文末内容。后续已补充 M² 与 AgentProg 的记忆方法核查，阅读范围、原文补查及待读清单见[记忆方法核查](../03_策略与论文方法/记忆方法核查.md)。EffGen README 指向框架论文 arXiv:2602.00887，尚未读取该论文，不能用 README 代替框架研究结论。

《Read More, Think More》的问题是：减少观察是否仍然普遍有利，以及模型能力、推理预算怎样改变答案。其设计对比当前观察表示、推理预算与观察历史，而不是仅证明一种压缩算法。核心判断是把“观察越短越好”改成“观察表示应匹配模型和任务”，并将历史差分作为成本较低的历史保留方式。

实验支撑评分：8/10，足以支持其基准内的核心故事。任务记录保留必要出处：§3.1 的 WorkArena L1（330项），§3.2／表1–3 的表示对比，§3.3 的 grounding 错误分析，§3.4／表5 的历史对比。历史实验固定当前观察为 AX，差分针对旧观察；原文没有证明比赛 Qwen3.6-35B-A3B 的最优表示，也没有证明布局线索是 HTML 收益的唯一原因。

对本项目的设计含义：第一阶段先保留可重放的原始观察与动作证据，不预先把 DOM 剪枝、历史差分或截图理解设为默认增强；相应机制进入后续单变量实验。历史元素编号不能成为当前动作的有效定位依据。保留接口与原始证据属于可验证的工程准备，具体收益仍由后续批准的实验判断。

事实核查评分：9/10，当前核心结论由本地源码、ZIP 内容和论文全文直接支撑；新版 SDK 的接口清单仍需单独获取核对。
