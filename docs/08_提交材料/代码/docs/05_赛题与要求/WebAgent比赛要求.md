# WebAgent 比赛要求

赛题：华为 2026 年度 Hackathon 软件难题挑战赛决赛第 30 题——Web Agent 的并行执行与容错调度。

整理日期：2026-10-30。本文汇总赛题原文、群内补充、接入指南和验收说明。验收安排依据验收说明，当前调测操作依据接入指南与群内能力答复；评分权重及报告要求保留原题条款。

## 一、要完成什么

开发一个接收自然语言任务指令、自动操作网页完成业务任务的 Web Agent。自行实现任务拆解、页面理解、行动决策、结果确认和容错恢复，在保证成功率的基础上缩短耗时、减少冗余操作与模型调用。

| 能力 | 要求 |
| --- | --- |
| 并行执行 | 在真实网站用例中识别依赖与并行空间，协调页面、子任务和共享状态。 |
| 结果确认 | 根据实际网页状态判断动作结果，合理安排检查时机。 |
| 容错调度 | 发现超时、元素缺失、登录态失效等异常，回退、恢复并重新调度。 |
| 频率控制 | 在网站限流规则内安排访问频率与并发数量。 |
| 人工衔接 | 识别登录、二次验证等环节，主动暂停并提示用户，完成后自动恢复。 |

## 二、验收内容与安排

验收由 **10 个自动化用例＋1 个真实网站用例**组成。

| 项目 | 自动化用例 | 真实网站用例 |
| --- | --- | --- |
| 环境 | 赛方部署的论坛、电商模拟网站 | 公开真实网站 |
| 用例公布 | 原题规定决赛现场公布 | 验收阶段公布目标网站与任务 |
| 完成判定 | 程序化校验器检查最终页面内容、目标地址或后台数据 | 视频连线现场查验 |
| 重点 | 完整完成任务、结果正确、稳定执行 | 真实交互、多 Tab／多子任务并行、限流合规、用户接管与恢复 |

真实网站演示须展示页面操作、多 Tab 切换与并行效果，以及相对串行执行的耗时收益，并支持用户接管；进阶方案可在该场景实现和展示。比赛阶段自行在公开站点验证。

**比赛阶段**：各队本地开发 Agent，连接共用调测服务器联调，查看结果与回放。调测入口：[WebArena 评测台](https://webarena.94-74-111-115.sslip.io/)。

**验收阶段**：比赛结束后，赛方公布最终验收服务器地址；各队登录并连接 Agent，逐队视频连线，按评委指令执行用例，共享操作过程与日志，当场核对成绩。

**最终成绩以验收阶段的服务器结果和现场查验为准；调测成绩仅用于联调。**

## 三、模型与运行环境

| 事项 | 要求 |
| --- | --- |
| 主模型 | 统一使用 **Qwen3.6-35B-A3B（35B MoE，激活 3B）**。 |
| 辅助模型 | 如使用更轻量的模型辅助，须报备。 |
| 平台调用 | 自动化评测通过 `third_party_agent.model.generate(messages)` 调用统一模型，选手不指定模型、密钥或推理参数。 |
| 开发环境 | Agent 在各队本机运行，开发语言与框架不限；群公告暂不限定鸿蒙工程，接入程序要求 Python 3.10+。 |
| 服务器职责 | 提供模拟网站、浏览器、统一模型调用和判分。 |
| 网络连接 | 本地客户端主动连接评测台，无需开放入站端口。 |

验收说明称届时提供 API Key；当前自动化接入由平台管理模型与密钥。真实网站的模型接入方式待赛方明确。

## 四、平台接入与调测

### 1. 注册与连接

1. 使用本队评测台账号登录，首次使用时注册。账号保管要求见第五节。
2. 下载 `webarena-outbound-client.zip` 并解压。
3. 在「Agent 连接」中新建连接，下载 `agent-connection.json`。连接令牌只在创建时下载一次，不是模型 API 密钥。
4. 将连接文件与 `third_party_agent/`、`my_agent.py`、`agent_logic.py` 放在同一层目录。
5. 在 `agent_logic.py` 的 `decide()` 接入自己的策略，通过 `my_agent.py` 适配平台输入输出。
6. 在客户端根目录启动连接：

```bash
python -m third_party_agent connect --connection-file agent-connection.json --agent my_agent:MyAgent
```

保持客户端与电脑运行，在网页确认「已连接」，再启动任务验证实际操作。连接包提供统一模型 baseline；另有仅返回 `stop` 的 `ExampleAgent`，用于验证连通性。

### 2. 输入与动作协议

- 输入包括任务、当前页面观察（类型、URL、可访问性树文本及可选截图元数据）、历史、动作历史和任务内状态。
- 一个请求只返回一个动作，可返回动作字符串或 `{"action": "click [当前元素编号]"}` 形式的字典。
- 常用动作包括 `click`、`type`、`press`、`scroll`、`goto`、`stop`；完整格式见连接包 README，元素编号须来自当前观察。
- 可替换提示词与决策逻辑，在本机安装算法依赖；自带浏览器框架须适配平台观察与单动作协议。
- 自动化评测网站不支持多 Tab，不开放 curl 与 JS 注入。[最新平台更新](结构化资料/06_网页截图能力更新.md)已开放当前视口 PNG：新版客户端通过 `observation.screenshot` 与 `browser.get_screenshot/save_screenshot` 下载，截图与 AX 同步采集，下载和本地处理计入原任务预算；统一模型仍只接收文本，不开放坐标动作。原连接文件可复用，同一令牌须先停止旧客户端再启动新版。

### 3. 批次执行与结果

在「评测总览」选择在线 Agent，点击「开始整批评测」。当前接入指南规定按固定顺序执行调测任务，浏览器就绪后每项限时 **300 秒**、不限步数，截止后检查最终状态。最终验收时限待公布。

2026-10-30平台已扩充为论坛6项、电商2项，共8项；两网站分别启动整批，按顺序执行。实际清单与版本见[调测任务扩充](结构化资料/07_调测任务扩充.md)。这不改变最终验收10项的要求。

接入指南所述论坛调测每项创建新副本并启动独立浏览器，结束后回收副本，网站数据由平台恢复。可关闭或刷新评测网页，但须保持本地连接程序运行。停止整批执行会停止当前与后续任务，已完成结果保留；某项持续无响应时，平台会停止该项并继续后续项。

在「运行记录」查看详情和 HTML 操作回放，下载评分 JSON、浏览器 trace、日志及批次报告。回放包含页面文字、动作和截图；模型 token 用量与费用由平台记录、统一结算。

| 平台结果 | 含义 |
| --- | --- |
| 已完成，1 / 1 | 校验通过。 |
| 已完成，0 / 1 | 已判分，任务目标未满足。 |
| 运行失败／已中断，未评分 | 结果尚无有效评分，原因见日志。 |
| 已取消 | 没有有效评分。 |

当前论坛平台不提供实时可操作的远程窗口；真实网站演示须另外具备用户接管能力。

## 五、执行、日志与账号规则

**每队同一时间最多运行一个官方评测任务，按顺序提交和执行。**

每次自动化任务执行前恢复初始数据，结果按账号隔离。一队一账号，注册后妥善记录，平台不提供账号找回。验收全程使用并提供本队账号，Agent 操作、日志和评测记录须一一对应。账号遗失或无法提供时，相关记录不予认定。

运行日志须完整，至少包含：**操作时间、目标页面、动作类型、结果、模型调用量**。

验收纪律：

- 模型与辅助模型按第三节执行；验收说明禁止调用其它高规格云端模型、外部 API 或外部算力。
- 禁止绕过网页直接篡改数据、预写死任务答案、伪造日志或使日志与实际操作不符。
- 禁止账号混用、借用或冒用他人评测记录。

违反验收纪律可能导致任务记 0 分或取消成绩。

## 六、判定、计时与评分

自动化用例在任务声明完成后执行程序检查。单用例结果为**通过／不通过，无部分分**；失败或超时记为该任务未完成，计入整体通过率，其它任务继续执行和判分。

**验收通过率不低于 60% 方可进入排名。** 真实网站用例的计分和通过率口径见第九节。

计时从任务指令下发起，到验收检查执行时止；登录、二次验证等人工干预时段扣除。

| 维度 | 权重 | 评价内容 |
| --- | --- | --- |
| 成功率与鲁棒性 | 45% | 整体验收通过率、失败后的恢复表现。 |
| 完成时间 | 20% | 已通过任务的总耗时，扣除人工干预，按排名分档。 |
| 操控质量 | 15% | 操控流畅、无冗余操作、等待合理、性能与资源占用；人工环节识别和衔接从优。 |
| 成本控制 | 10% | 页面访问次数与模型调用消耗。 |
| 方案报告 | 10% | 各考察点的设计分析质量。 |

以上为原题评分条款，验收说明未重列权重。原题另有小模型酌情加分条款，其在统一模型要求下的适用方式待明确。

- 真实网站用例公布后，目标站点和演示流程就绪。
