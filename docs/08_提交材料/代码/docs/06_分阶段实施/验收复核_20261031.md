## 已复现、影响验收的问题

### 1. L03 会接受与任务无关的截图

在隔离本地网站完成 20 条编辑与取消，不拍任何编辑后截图；全部取消后只拍一张主页截图，将同一文件分别声明归属 20 个帖子。提供真实 PNG 和正确 SHA-256 后，统一 judge 返回 `pass`、`evidence_count=20`。

因此当前判定不能证明每条编辑后、取消前的截图，也不能保证截图属于对应对象。D06 不能仅凭既有 judge pass 关闭。实现位置：`testing/evaluation/judge.py::_verify_screenshot`、`_screenshot_audit`；复现截图为 `final/wrong-screenshot/homepage-only.png`。

### 2. 自动接管恢复后可能在旧观察上结束

沿用 L06 的真实浏览器、控制协调器和模拟用户，仅将模型在恢复后的第一轮输出改为 `Final Answer: done`。循环返回 `completed`；外部 judge 判失败，`draft_cancelled` 未完成。

`control/loop.py` 第 337 行先把接管前反馈送入生成器，第 346 行遇到非 ACTION 直接返回；真正的 `backend.observe()` 在第 366 行才发生。此次 `resumed` 事件写出 `fresh_observation_installed`，绑定的却仍为接管前 `obs-4`。这同时影响恢复正确性与审计记录，E05/E06 不能完整通过。

### 3. 最小核验与纠错没有进入官方入口

`official_agent.py` 第 364 行创建普通 driver，没有传入状态工具、完成核验回调或控制协调器。当前 completion gate 位于生成器已经返回之后，仅接上它也无法保证同循环继续；`request_finish` 工具虽已实现，官方入口尚未注册。

实际入口重放空文本不提交时，返回 `stop [task not completed due to local error (ActionRejected)]`，只调用一次模型；没有将纠正信息交回后续模型轮。故 P01/P03/P04 尚未关闭。

### 4. L04–L07 的统一判定入口仍不可用

逐个调用 `start(case_id, 101).judge()`，L04/L05/L06/L07 全部抛 `JudgeDispatchError`。已注册 checker 仅 `field_replacement`、`l01`、`l02`、`l03`。新增 L15 可以走统一入口，不等于已有恢复／接管任务已接通；现有 E 用例依赖测试 helper 的专用判定。

### 5. 已核验目标的恢复仍断在控制器

`StateStore.invalidate_goal` 已合入并可独立调用，但 `recovery/controller.py` 第 216 行仍对 verified 目标返回未应用结果。这保持了诚实拒绝，却没有达到 E03 要求的已确认进度受影响时程序化失效。

### 6. 当前工程环境与交付说明未闭合

`uv pip check --python .venv/Scripts/python.exe` 报告唯一不兼容：EffGen 要求 `aiohttp>=3.14.3`，当前为 `3.12.15`。这是 browser-use 试验遗留，现有测试通过不能替代依赖一致性。

`code/harness/README.md` 第 304 行仍声称会转义方括号、反斜杠及换行，第 555 行仍声称原生 prompt 预算接入未完成，与最终源码及接入修复记录不一致。远端 master 对应旧关闭提交，不能覆盖本次未提交修改的可复现交付。
