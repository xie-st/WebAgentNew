# 第三阶段：实验验证

状态：2026-10-31实验效率修订已按用户要求纳入方案，具体实施与实验批次待逐批批准。当前约90分钟执行窗口按[双环境测试、F/G开发与实验并发方案](../07_双环境测试_FG开发与实验_并发方案.md)，同时安排官方与真实测试、F/G新增功能和就绪机制实验；本文不作为前两阶段的实际完成记录。

## 目标与起点

用可重复的实验决定哪些机制值得保留，形成最终配置、双环境演示和3–5页报告。沿用第二阶段网站、任务、EffGen循环、工具和日志，不另建实验平台。

沿用本地可重置任务、赛方论坛／电商与真实网站三层评测，暂不另行部署WebArena。赛方任务作为本项目主要外部基准，本地用例补足故障与状态控制；两者成绩和用途分开，不声称运行了完整标准WebArena。

进入前固定第二阶段交接提交、模型服务与版本、SDK、浏览器、任务清单、判定器、配置和已知问题。第一阶段的换行、请求限额与deadline收尾及当前批次所依赖的生产接线、开关、预算、判定须有验收证据。当前批次可与尚未涉及的F/G开发并发，未通过的可选项保持关闭；完整第二阶段交接仍须D–G与H项证据。缺项由原阶段关闭，不把接入修复当成策略收益。[验收复核](../验收复核_20261031.md)发现的生产接线、统一判定、逐条截图证据、恢复重观察等缺口须有后续关闭证据；不得以本轮调度修订视为通过。

先核对EffGen原生轨迹、记忆、预算、压缩、工具与工作流的实际配置。项目历史开关全关闭不代表原生压缩关闭；基线必须写出实际执行路径。模型仍为比赛允许的统一模型。

## 实验原则

每批回答一个问题，只改变一个机制或一个参数，其他条件相同。单项实验以冻结基线为对照，不将上一项的改动悄悄累加。若比较已有候选组合，须另列新对照。

任务、数据、故障和模型预算成对匹配；两组均从干净状态开始，交替安排A/B与B/A顺序。网页数据种子固定不等于模型输出可完全复现。失败、超时和取消保留在原分母，重复试验按原先约定运行，不只挑成功的一次。

基础接线验收后先取得当前版本官方基线。单项候选先经离线机制验证与少量本地真实模型筛选，有依据者在P1就做获批的官方对照，用反馈决定是否继续投入；P2做组合与独立回归，P3保留最终完整复验。官方成绩、内部核验和本地外部判定分别报告，不混成一个完成率。

## 四步安排

| 批次 | 工作 | 交回内容 |
| --- | --- | --- |
| P0 | 固定版本、指标与任务分组，确认重置与生产接线，按获批清单取得当前官方基线 | 基线版本与完整结果、原生配置、预算、失败归因及首批申请 |
| P1 | 并行准备获批候选，逐项本地筛选；有依据者尽早做官方开关对照，真实端并行另排 | 每项成对结果、淘汰／保留／未定判断及下一批依据 |
| P2 | 组合少量有依据的候选，做移除单项检查与独立回归 | 候选配置、交互影响、回归结果 |
| P3 | 最终配置在官方与真实端复验，整理演示与报告 | 最终版本、完整成绩、证据、3–5页报告初稿 |

P1是候选清单，不是一张获批后全部自动执行的矩阵。每项先提交问题、对照与改动、任务、运行次数、预算、指标和停止条件；获批后运行，交回结果再决定下一项。采用成本较低的相关用例筛选，证据不足时保持未定，不自动扩样。

候选选择按[实验清单](04_实验清单与记录.md#p1候选实验)：官方方向先考虑核验时机与停滞恢复；后续由当前失败轨迹、历史长度、输入量、模型等待与返工成本决定，逐批重排。真实端串行／2分支另列，与官方候选分别安排。原有独立回归及最终双环境验收继续保留；不为凑足实验而扩展候选。接口不支持的截图理解和推理配置不投入实施。

## 并行准备与串行验证

在当前批次申请中分别列出本次效果实验、可并行准备的后续候选、文件归属及各自预算。用户只批准当前实验时，后续仅整理已有证据与申请，不自行实现。每项效果实验仍须获批，交回结果后等待用户决定下一步；预备工作批准不包含后续真实模型调用或官方启动。同一实验的各层任务、预算与条件可在一份批次清单中一次批准；已覆盖的条件执行无需重复请批，未覆盖的运行另报。

官方测试冻结版本A时，多个DSH可在独立源码副本中并行完成获批候选实现、离线契约验证和已有训练轨迹分析。共享入口、提示词、配置注册与CLI由一人顺序集成；只集成当前候选，其他开关保持基线，避免把多项变化带进一次对照。

每次运行使用独立冻结目录或固定提交，记录源码、依赖、配置、经验与任务版本。启动前确认实际导入该版本，不经可变开发目录或共享可变配置加载；批次运行结束前不修改冻结产物。凭据由主线程注入，不复制给worker。资源紧张时暂停开发重负载，避免影响计时。

正式计时对照顺序运行，避免争抢模型、浏览器与站点配额；官方始终单在途，按平台支持的套件／整批启动。官方与真实功能测试按当前并发方案，在独立服务／配额或有效共享限流条件下尽量重叠；功能测试存在并发负载时记录条件，不直接充当计时对照。DSH离线工作不占用官方执行窗口或实验模型配额。真实端并行是EXP-08的被测变量，其首版限独立只读分支、共享写串行。

依据准备、集成、本地筛选、官方运行的实际耗时调整后续分工。候选准备已快于测试消化时，DSH优先做验证与归因，不继续堆积候选。清单、快照和既有脚本足以组织，不新增调度服务。

## 分层筛选与基线复用

离线检查机制与变量生效，失败者返回实现修正，不占真实模型名额；通过者用少量相关本地任务做真实模型对照，达到预先批准的继续条件者才进入官方对照；清单已覆盖时按批准条件执行，未覆盖时另报。样本、继续／淘汰／未定规则和预算均在运行前确定；每层保留原始清单与全部结果，不把各层分母拼在一起。证据不足交回用户，不自动扩样。

同一冻结基线可作为多个独立候选的共同对照，但仅在任务／初态、模型、依赖、预算、资源条件与时间窗口可比，且运行前批准复用范围时使用；保留共同对照身份，不把一次基线当多次独立观察。代码修复、基础配置或平台版本变化时重新建立基线；旧两批4/6不替代接线后的新基线。最终回归与P3复验仍独立运行。

## 单项实验范围

| 方向 | 要回答的问题 | 实现约束 |
| --- | --- | --- |
| 历史 | 同轮摘要、旧观察差分、已完成目标折叠分别是否有帮助 | 沿用原生压缩入口；三项分开比较，必要事实与当前观察保留 |
| 观察 | 任务相关筛选能否减少输入而不漏目标 | 保留当前合法AX映射和回退；关键词生成及回退成本一起统计 |
| 核验 | 增加哪些过程检查能减少错误完成和返工 | 保留最终完成检查、未知副作用先取证与禁止发送等基本约束，只比较额外检查时机 |
| 恢复 | 停滞触发参数、短反思是否改善续做 | 参数和反思分项比较；不关闭截止、接管和副作用保护 |

## 经验形成与轨迹分析

教师模型出题和反馈属于单独批准的离线工作，只接触训练组的自建任务、允许使用的轨迹和反馈。教师身份、接口、费用与赛规适用性确认后再调用；实际执行与线上核验仍使用比赛允许的模型。DSH开发worker与实验教师的职责分开。

从训练轨迹提炼通用指导或有限组合，保留来源、前置条件、核验条件和版本，经人工选择后冻结。新对象、不同布局与故障条件下重放，检查指令遵循及泛化。对经验生成、选择与执行分别记成本，不把离线构建成本藏掉。

轨迹诊断只在副本中标记重复访问、无贡献分支和必要依赖，原始日志不改。焦点、登录、草稿和副作用核实可能是必要动作，不能因没有新文本就删除。所得路径称“本轨迹可删冗余的候选”，不用离线回看冒充在线预知或全局最短路径。候选须在可重置任务中重放验证后才能形成经验。

本阶段不默认训练模型权重，也不为每个方向安装额外服务。扩展到训练或新模型时另写实验与预算。

## 评价与取舍

优先看完整完成率和任务约束，再看时间、调用、token与返工。假模型只检验程序行为，不进入策略效果统计。网页操作、内部工具和额外语义调用分别记录，根任务汇总所有分支与失败尝试。

报告所有尝试的耗时与结束原因；成功耗时同时给出两组各自的样本数和共同成功任务的成对结果，避免以丢掉困难任务换取“更快”。真实端分开总耗时、人工接管时间与有效执行时间；官方采用平台执行窗口，不扣除人工或排队来延长300秒。

费用有完整计价依据时才报告金额；否则报告token和调用量，金额记未知。平台调用、本地尝试、正常返回、失败分别计数，沿用C批复核确定的口径。

小样本只用于筛选。若候选出现无法解释的原有通过任务退化，先定位，不立即提升为默认；没有足够收益时保留更简单的基线。最终取舍由用户根据本批证据确认。

## 双环境验证与交付

官方端按实际可用任务和最新规则顺序运行，保持每任务单动作、单模型请求，不按题号写答案。真实端保持浏览器渲染与实际操作，登录、验证走接管。赛方小红书案例继续逐条编辑、截图、取消，禁止发送；至少20个不同对象的要求不降低。

最终串并行展示使用同任务、同模型、同限流和预算。真实网站无法恢复相同初态时，记录页面与对象变化，结果作为现场演示，不给出严格的因果加速结论。

交付最终配置与版本、各批实验记录、失败与未知项、双环境证据和报告初稿。报告区分工程能力、单项实验结果和现场演示。后续合并与发布按用户授权执行。
