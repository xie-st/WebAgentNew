# 第三阶段实验清单与记录

状态：2026-10-31效率修订已纳入方案。本文定义候选、分层筛选与记录方式，具体批次逐批审批，不授权批量运行。

当前约90分钟并发窗口按[双环境测试、F/G开发与实验并发方案](../07_双环境测试_FG开发与实验_并发方案.md)：官方与真实功能测试、F/G新增功能、实验准备同时推进；预留F的EXP-08与G的EXP-03各1对探索实验，分别满足进入条件后运行，不替代下列长期候选清单与最终回归。

## 评测环境与用途

保持现有三层评测，暂不新增独立WebArena或BrowserGym部署。

| 环境 | 测什么 | 结果用途 |
| --- | --- | --- |
| 本地可重置网页，沿用L01–L14 | 记忆、核验、故障恢复、接管、并行、限流；由外部判定器核对结果 | 单项机制对照与定位问题 |
| 赛方论坛／电商平台 | 完整任务通过情况、耗时、操作、调用和token；按平台判分 | 本项目主要外部效果基准；覆盖论坛与电商，并保留未调参任务 |
| 真实浏览器网站 | 实际交互、截图、多Tab、接管恢复；当前参考任务为至少20条不同帖子逐条草稿、截图、取消且不发送 | 真实任务验收、串并行展示及演示证据 |

三层结果分别报告。自建任务不单独证明通用能力提升，赛方任务不标称完整标准WebArena成绩。调测任务与最终验收任务分开，任务版本和范围在运行前冻结。

按[已收到的赛方材料](../../05_赛题与要求/WebAgent比赛要求.md)，评分维度为成功率与鲁棒性45%、完成时间20%、操控质量15%、成本10%、报告10%，进入排名的通过率门槛为60%。本项目实验对应记录完整完成率、耗时、无效操作、调用与token，官方最终成绩以平台和赛方实际判定为准。

## 任务分组与小批次

复用第二阶段本地L01–L14及其生成器、故障和外部判定。seeds101／202／303用于开发与训练，404／505保留给最终回归；同一seed不是同一模型随机输出。需要超出已有任务的新泛化任务时，在评测前固定，生成器与判定器分开保管。

筛选分为离线机制验证、本地真实模型对照、官方候选对照。先检查实际入口、变量生效与判定正确，再为通过者选与假设直接相关的少量开发任务；本地已有依据的官方适用候选在P1就做获批平台对照。各层的任务、次数、继续／淘汰／未定条件与预算在运行前批准，可纳入同一批次一次批准；已覆盖的条件执行不重复请批。各层结果分别报告，按获批批次交回。假模型只验证机制，不证明效果。

“2用例×3开发seed×A/B各一次，共12次”保留为可选清单，不作为每项配额。L03等长任务可在批准前缩小初筛范围；用于最终真实任务验收时仍须满足20个不同对象。清单冻结后不按表现缩小分母，证据不足交回用户，不自动补跑。

只有准备提升为默认的候选才申请重复与扩样。模型波动需要重复时，预先固定轮次和顺序；同一任务的重复结果按任务聚合并保留离散情况，不把重复次数当成新增独立任务。最终回归另批批准，范围至少覆盖受影响能力及原有通过任务。

开发组可用于调试、教师出题反馈和经验提炼。回归组不进入任何优化提示词、经验库、教师输入或样本选择；候选和判定规则冻结后才运行。若交接时404／505已被用于优化，先替换保留组。保留seed首次反馈一旦用于改动，就不再称该任务未见。

相同生成器的新seed检验跨实例迁移，改变布局检验跨布局迁移；它们不自动证明跨任务类型泛化。需要新任务类型时另批预先固定，报告分别说明迁移范围。

## P1候选实验

各项对照默认是本批所依赖能力已验收的当前冻结基线加且仅加表中变量；尚在开发的其他能力保持关闭，完整阶段交接另行验收；基线实际值不同时，运行前调整对照并获批。EXP编号与单变量问题保持，表中分组表示选择条件，不是固定执行序列。

官方效果方向先考虑核验时机与停滞窗口；随后依据新基线中的错误完成、重复动作、历史长度、输入token和模型耗时，按预期收益、成本与依赖选下一项。EXP-08在真实端单独安排，不作为官方固定第三项。每次报告提出当前最值得验证的问题及依据，不要求全部运行。

| 选择条件 | 实验 | 唯一变量与问题 | 相关本地用例 | 前置条件 |
| --- | --- | --- | --- | --- |
| 官方优先 | EXP-05 | 一种额外过程核验时机对另一种：是否减少错误完成和返工 | L03、L04、L05 | 基础结束检查、未知副作用核实与操作约束始终开启；清单指定具体检查节点 |

| 真实端另排 | EXP-08 | 同一任务图串行／2分支；如有依据再另批比较2／4 | L08、L09、L10、L11 | 真实端独立只读任务、共享写串行；相同模型并发、站点节奏、根预算与计划输入；官方不运行并行 |
| 完成历史冗长时 | EXP-03 | 完成过程展开／折叠：关键值与恢复能力是否保留 | L03、L05、L13 | 账本与原始证据固定，失效目标可重新展开 |

P2只组合已分别验证的所选机制，不要求先跑完EXP-01–04，也不全排列开关。核验、停滞与反思分别比较，不将三项一起变化称为单变量。

附加A–F保留在[备选文档](05_补充实验候选_待选择.md)，当前不加入主线；用户选中后才补具体对照。独立实现、配置和离线分析可并行准备，计时对照顺序运行，不因并行方便而改变优先级或混合变量。

## 官方队列与基线复用

P0在生产接线及判定验收后，按批准范围取得当前官方基线；首批本地有效候选在P1做官方对照，不等所有单项与组合完成。论坛与电商按平台实际启动单位排队，官方始终单在途；如平台只支持整批，预算和运行数按整批任务计算，不虚构抽选单题。平台不能恢复同初态时按实际可比范围报告。

官方运行冻结版本A期间，可并行做已批准的F/G新增功能、候选实现、离线验证与已有训练轨迹分析；真实功能测试资源条件允许时也可重叠，计时对照另留独占窗口。下一次效果运行须单独获批并通过集成、冻结与导入核对；准备速度已足够时优先做归因与验证。计时实验不共享实验模型配额、浏览器与站点负载，DSH重负载可能影响主机计时时暂停。

同一基线仅在源码基础行为、依赖、配置、任务版本／初态、模型、预算、资源与时间窗口可比且预先批准时复用。各候选引用相同原始run，明确共同对照与相关性，不重复计作独立样本；需要独立重复时另批批准。修复或条件变化后重新建立基线，旧4/6仅作历史记录。未用于开发的回归任务与P3最终复验不以复用代替。

## 并行的两层证据

先在本地使用同一预定任务图、页面延迟和数据，比较调度差异。任务图只用当时可见任务与信息生成，不使用未来观察或隐藏答案。两组相同图、模型并发与限流，记录动作、等待和关键路径。

再在真实网站进行同任务系统验证，EffGen仍可按实际反馈改计划；如果实际任务图发生差异，报告为系统整体效果，不能全部归因调度。无可重置初态时作为演示。根墙钟时间不能用分支耗时之和代替；人工暂停按全局区间计一次。

## 教师与经验子批次

先用少量自建训练任务检查统一模型对工具契约、禁止发送、完整目标和经验前置条件的遵循，程序判定结合人工核对。需要教师改进指导时，再单独提交教师身份、输入材料、样本数、费用或token上限和产物用途；未经确认不调用新服务。

流程为训练任务与轨迹→候选反馈／通用指导→人工选择→冻结批准版本→新对象／布局验证。保留被拒候选与理由。教师不得访问官方隐藏判分、保留任务或未获准外传的真实内容；经验不含任务答案、题号特判、固定帖子链接或过期元素ID。

文本经验与可执行组合分开计效；线上只加载冻结批准版本，不边测边改库。离线生成成本、人工筛选时间和执行成本单列，必要时同时报告单次执行成本与含构建成本的累计值。

## 运行清单与记录

每批记录以下内容即可，沿用已有YAML／JSON和run日志，不引入新数据结构：

- 批次：batch_id、问题、唯一变量、筛选层级与继续条件、基线与处理配置／哈希、效果运行及并行准备各自的批准范围。
- 来源：冻结代码与依赖、SDK、模型服务及实际参数、浏览器、原生策略、工具与经验版本；实际导入路径、资源条件、基线复用来源及可比依据。
- 样本：case_version、seed、故障、任务分组、重复轮次、A/B顺序与pair_id。
- 预算：每run截止、根调用／token约束、各筛选层和准备工作预算、官方启动单位、整批最大运行数及执行时间；金额不明时不伪造金额上限。
- 结果：run_id、attempt_id、平台标识、判定来源、完整成功／失败／未知、结束原因、约束违反、证据和缺失项。
- 决定：保留、弃用或证据不足，依据、准备／集成／筛选／官方执行的实际耗时及下一批待批准的问题；按证据重排候选。

总运行数、执行时长上限和调用约束必须能在启动前检查并在运行中生效。token只可估算时写明计数方法与预留量，以调用和时长限制兜底，最终对账实际用量。并行、重试和教师调用不得绕过批次预算；教师离线预算与执行预算分别列出再汇总。

## 指标与停止条件

| 指标 | 口径 |
| --- | --- |
| 完整完成率 | 每组满足全部条件的首次计划运行数／该组原始计划运行槽位数；每槽位由case、seed和重复轮次确定，错误／deadline／未执行单列且不从分母静默删除；run内恢复计入本槽位，额外整任务重跑另列、不替换原成绩；回归另给按独立任务聚合的结果 |
| 完成数量 | 唯一对象且每条条件全部满足才计数；访问、截图或Agent自报不替代完整完成 |
| 耗时 | 全部尝试按结束原因报告；共同成功样本给出成对差值；两组成功集合不同须展示，不能只比较各自最快样本 |
| 人工时间 | 总耗时、全局接管区间与有效执行时间分列；官方以平台执行时间口径为准 |
| 操作质量 | 重复输入、无效提交、已确认目标返工、未知副作用重发、核验误报／漏报；外部判定与内部判断对照 |
| 模型与成本 | 根任务全部实际尝试、平台记账调用、输入／输出token、失败及额外摘要／反思／核验；费用缺失为未知 |
| 回归与波动 | 各任务成对胜／平／负与重复结果；不以一个平均数遮盖原有任务退化 |

小样本原样报告计数和差值，描述为探索结果。需做区间估计时以任务为配对单位保留组内重复结构，方法与样本数写明；不因未显著就自动多跑，不事后改主指标。

出现协议／状态隔离错误、禁止动作或未知副作用被重发时停止；根预算耗尽时停止；其他失败按清单继续或结束。没有预算外自动补跑。外部环境故障与决策失败分开标注，原始清单与结果保留；修复后重做的对照另立批次。

## P2、P3与报告

P2优先比较冻结基线与一个小候选组合；结果异常时逐项移除定位，不开展全组合搜索。候选冻结后运行未见回归；据此调参后须更新任务使用状态及版本。

P0与P1已产生的官方结果用于早期取舍；P3仍按最终冻结配置和获批清单完成官方串行复验与真实端证据，不以开发成绩替代最终结果。不同套件、网站、版本、时间窗口分别报告；不把C批旧成绩与新成绩直接拼成提升。官方若不能恢复同初态，说明比较范围，不虚构随机对照。

3–5页报告初稿包含问题与实现、固定条件与任务、主要实验与反例、最终配置与双环境结果、成本和证据索引。文字以实际数据为准，不预写收益数字；论文只作为方法来源，引用项目已有核查材料。
