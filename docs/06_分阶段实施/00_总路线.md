# 总路线

状态：第一阶段已跑通，线上复核接入收尾待验证；第二、三阶段详细文档已成稿，具体实施进度以[任务记录](../01_路线与框架/提示词&任务进度.md)为准。更新：2026-10-31。原始需求见[RoadMap](../01_路线与框架/RoadMap.md)。

目标是让 EffGen 持续负责规划、行动、核验和恢复，同一套网页工具分别接官方平台与真实浏览器。外围程序负责环境连接、事实保存、协议检查和日志。

## 三阶段

| 阶段 | 完成什么 | 验收结果 |
| --- | --- | --- |
| [一：双环境跑通](阶段一_双环境跑通/01_详细方案.md) | 固定源码与 SDK；接通模型；实现动作交出和观察返回；接真实浏览器；保存日志与截图 | 两端各完成一个真实任务，证据能对应；工程可从干净环境安装运行 |
| [二：基础能力与测试环境](阶段二_基础能力与测试环境/README.md) | 状态账本、过程核验、恢复、接管、多 Tab 调度、限流；配置可重复的测试任务 | 能验证任务进度、处理异常并恢复；各机制可以独立开关 |
| [三：实验验证](阶段三_实验验证/README.md) | 固定任务与版本，逐项比较设计，保留回归任务；形成演示和报告依据 | 每项保留的设计都有结果支撑，串并行收益、时间与成本口径明确 |

第一阶段跑通不等于整体完成率达标。第二阶段建立能力与测试条件，第三阶段决定哪些设计值得保留。

| 原始要求 | 安排 |

| Playwright 与 browser-use 分别尝试 | 第一阶段做同任务接入试验；选择初始后端，保留另一端结果 |

| 状态账本、任务验收条件 | 第一阶段留存事实，第二阶段加入子目标与完成条件 |
| 核验时机、因果归因、保留进度和断点恢复、Reflexion | 第二阶段实现基础流程，第三阶段比较策略 |
| 历史折叠、历史差分、同轮摘要、Prune4Web | 第二阶段提供开关，第三阶段单项验证 |
| 多 Tab、依赖调整、共享状态、限流、用户接管 | 第二阶段；第三阶段比较串并行效果 |
| 先记忆后 skill；教师出题反馈、经验泛化；动作组合与最短路径分析 | 第二阶段定义经验格式与加载接口；第三阶段审批后生成、重放与验证 |
| 成本与时间门控、上下文控制 | 第一阶段建立预算和记录；第二阶段补充决策策略；第三阶段调参 |
| 推理强度 | 仅在接入允许时实验；官方接口固定参数，不能发送不支持的配置 |
| 固定任务、单变量、版本留痕、独立回归 | 第一阶段形成基线，第三阶段逐批执行 |

## 当前并发窗口

按用户最新要求，官方与真实环境测试、F/G继续开发、效果实验三类工作同时交付。当前约90分钟的分工、预算和版本切换见[并发执行方案](07_双环境测试_FG开发与实验_并发方案.md)。主线程负责运行与单人集成，DSH分担F新增功能、G新增功能和实验准备；官方始终单在途，真实功能测试在配额／限流条件允许时重叠，计时实验顺序独占运行。未验收可选功能保持关闭，其他已验证能力可先测试；完整阶段验收要求继续保留。

## 审批和执行

第一阶段按已批准方案分A、B、C批推进，接入收尾见[C批线上复核](阶段一_双环境跑通/验收记录/C_线上结果复核.md)。第二阶段按D、E、F、G批交回结果；第三阶段按P0当前官方基线、P1分层筛选与前移官方单项对照、P2组合回归、P3最终双环境复验交付推进。获批候选由DSH在独立副本并行准备，单人集成冻结，官方始终单在途；按最新失败轨迹滚动选择，真实端只读并行单独安排。详细文档已按2026-10-31用户要求完成效率修订。各阶段及每批实验的实施与复验范围以最新用户授权为准，文档成稿不等于已授权运行。

DSH 使用上级《子智能体.md》指定的 `ds-flash`、`fork_turns="none"`，沿用 high 推理设置。主线程处理仓库发布、凭据、安装和真实环境验收；DSH 负责明确范围的程序实现与离线验证。生产 Agent 只用比赛允许的模型；DSH 是开发工具，不进入比赛执行链。
