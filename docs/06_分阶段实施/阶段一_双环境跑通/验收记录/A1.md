## A2 可用协议

完整用法见 `code/harness/README.md`。A2 驱动生成器时应使用：

1. `Session(run_id, runtime_dir=..., budget=..., redactor=...)`；
2. `session.reset()`（reset 可以没有 task）；首次 ``step`` 取得完整 task 后 `session.start_task(task)`；
3. 每次新观察 `session.ingest_observation(observation)`；
4. 模型发出的全部工具调用交给 `guard_requests(requests, session.observation)`：
   - 多于一个网页动作 → `ActionRejected`（`multiple_actions`），整批不排队；把 `ActionRejected.correction` 作为格式错误回给模型；
   - 内部工具（`task_note`、`web_observe`、`evidence_save`）不放行成 `WebAction`；
   - 返回的单个 `guarded.action` 已绑定当前 run/page/observation/element 全引用；
5. `session.propose(action)` → `session.consume()` → `backend.execute(action)` → `session.ingest_observation(result.observation)`；
   `consume` 只能一次；dispatch 后的下一观察必须带同一 action 的 feedback；
6. `session.record_model_call(...)` 记录模型调用并检查 deadline/model budget；
7. `session.finish(Finish(...))` 记录 Agent 声明和终止原因（不写官方分数）；`session.close()` 幂等释放。

暂停/继续：

```python
session.pause()                 # 仅当无在途动作；丢弃未消费 proposal
fresh = backend.observe()       # 用户可能修改页面
session.resume(fresh)           # 必须是新 observation；旧定位表和旧动作立即失效
```

重要约束：

- `guard_requests` 与 `Session.propose` 都校验完整观察引用；同一数字在新观察中对应不同元素时，按新观察解析；旧观察动作被拒绝（`stale_observation`）。
- 两个参数相同的 `scroll` 只要分别绑定新观察，就是两个动作、两次执行、两次反馈；没有内容哈希去重。
- `proposed` / `dispatched` 事件的 `result` 必须为 null；`feedback` 才携带 `observed/error/unknown`。
- 每个模型调用、动作和反馈都通过 `EventLogger` 写入必需字段；日志、`result.json` 与异常消息统一经 `Redactor`。
- `web_observe` 返回 `session.observation`，A2 不应重新采集；`task_note` 可用 `session.add_task_note`/`session.task_notes`。
