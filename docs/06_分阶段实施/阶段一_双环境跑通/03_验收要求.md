# 第一阶段验收要求

状态：已批准，A 批实施中。与 [详细方案](01_详细方案.md)、[DSH 实施说明](02_DSH实施说明.md) 一起使用。

按下面编号记录通过、失败或未执行。离线测试由 DSH 完成，安装复验、真实模型、公开网页与官方运行由主线程完成。测试使用隔离环境和假凭据，不访问用户浏览器资料。

## A 批：工程和循环

| 编号 | 验收内容 | 通过条件与证据 |
| --- | --- | --- |
| A01 | 固定依赖来源 | EffGen 上游提交、快照范围、许可证、SDK 哈希和本地补丁可追溯；原始检出未被修改 |
| A02 | 安装与导入 | 在项目专用 Python 3.12 环境安装；导入 harness、vendored EffGen、官方 SDK；记录实际命令和依赖，不加载模型权重 |
| A03 | 同一循环暂停恢复 | 假模型先调用内部记录，再发两次网页动作，再读取先前记录并结束；每次 send 后保留 thread 与任务状态，不重建 Agent；网页工具结果只在反馈后出现 |
| A04 | 单动作与当前编号 | 模型尝试多网页动作、旧观察编号或错误页面时，不能发出动作；当前合法动作可执行；反馈中包含格式修正依据 |
| A05 | 普通路径回归 | 未使用交互入口的普通 Agent.run 与普通内部工具仍可运行；运行改动涉及的上游测试和新增回归 |
| A06 | 生命周期 | reset 缺少 task、不同 run 连续执行、暂停后 close、重复 close、取消均正确；上一任务状态不进入下一任务 |
| A07 | SDK 任务上下文 | 用两个独立的假 SDK 回调作用域推进同一生成器；模型只使用各次当前绑定。离开回调后无背景调用，无旧绑定泄漏 |
| A08 | 预算 | 假模型执行超过10个有效网页动作仍不被默认上限截断；deadline 到期后不再调用模型、下载或产生动作；内部空转也会结束 |
| A09 | 上下文 | 超预算时保留任务、当前观察和待确认信息；无法容纳时显式报告；官方请求不超过消息与字节限制，估算与精确计数分开 |
| A10 | 日志与脱敏 | proposed、dispatched、feedback 和结束声明可区分；必需字段齐全；模拟密钥、密码和令牌不出现在日志、提示词或异常中 |

A03 必须检查行为：第一次暂停时环境尚未执行，不能记录成功；第二次恢复的模型输入包含真实送回的观察；两个暂停之间的内部工具不要求平台发额外 step。仅断言生成器类型或调用次数不算通过。

A04 要覆盖“新观察再次使用相同数字但对应不同元素”的情况：有效性取决于完整观察引用，不能仅看数字曾出现。连续页面内容相同仍是新的观察，不能因内容哈希相同就跳过正常 step。

另用连续滚动两页的用例检查上游重复工具保护：两次 `scroll` 参数相同，但分别绑定新观察，必须实际产生两次动作并收到两次反馈；旧缓存不能代替第二次执行。重复消费同一待执行请求则应拒绝。

A08 的超过10步是离线合成用例，用于检查循环限制，不是新官方任务或模型实验。DSH 不为此调用真实模型。

A 批交回：离线测试报告、示例 events.jsonl、源码差异、安装说明，以及 B／C 仍待执行的项目。主线程复验后向用户交回结果，等反馈再进入 B。

## B 批：真实模型与浏览器

先运行可重复的本地网页夹具。夹具至少含输入框、搜索结果、分页和详情页，内容可用不同 seed 生成。任务由外部任务文件传入，执行器不包含题目到答案或动作序列的映射。

本地任务：按页面条件查找一个结果，打开详情，在草稿框填写任务给定文字，确认显示内容并保存截图，不提交。主线程使用统一真实模型运行；假模型回放仅算离线集成测试。

| 编号 | 验收内容 | 通过条件与证据 |
| --- | --- | --- |
| B01 | 真实模型 | 从本地配置读取凭据，以允许的统一模型得到实际响应；记录请求标识、耗时与 usage 来源，日志无密钥 |
| B02 | Playwright 本地任务 | 可见浏览器完整完成上述任务；页面可见结果与输入内容吻合；轨迹、截图和模型调用对应 |
| B03 | browser-use 接入试验 | 同一任务与工具契约，证明只使用其浏览器层。成功则交回运行证据；失败则交回版本、接口、最小复现与默认后端建议，交用户决定是否继续投入 |
| B04 | 暂停与继续 | 在输入前暂停，确认无在途动作后由用户手改页面；继续时重新观察，旧定位失效，Agent 根据新状态继续，不静默重放旧动作 |
| B05 | 公网页面 | 使用默认真实后端打开 `https://example.com`，报告网页标题和可见主标题，保存当前视口截图；禁止硬编码读取结果 |
| B06 | 证据与清理 | 截图能对应当时 URL、page_id、observation_id；关闭只释放自有浏览器与任务资源，不结束用户其他浏览器 |

B03 失败不自动否定 Playwright 运行结果，但必须交用户确认第一阶段后端选择后才能关闭该项。不能删去原要求或把 browser-use 的独立 Agent 演示当作 EffGen 接入成功。

本地夹具验证执行链，公开网页验证实际网络浏览。两者分别记录。B04 是人工触发的最小接管测试，自动识别登录、二次验证及完整状态恢复另在第二阶段验收。

B 批交回：统一模型信息、两个浏览器接法的记录、选定后端、真实截图、耗时与调用量。用户反馈后再进入 C。

## C 批：官方平台和交付

| 编号 | 验收内容 | 通过条件与证据 |
| --- | --- | --- |
| C01 | 官方模型契约 | 离线假网关核对只发送文本 role/content，无模型或推理参数、无工具 schema；异常重试仍计数，精确 usage 缺失为 null |
| C02 | 官方动作契约 | 中文、换行和括号输入处理明确；同源导航、AX 编号与动作格式符合冻结 SDK；不能用 DOM 编号或本机访问服务器内部 URL |
| C03 | 新旧观察能力 | 覆盖 AX-only、截图、HTML、DOM、不可用与过期；缺失新字段仍能决策；不复用上一帧冒充本次数据；原件完整性核对失败可见 |
| C04 | 官方连接 | 主线程确认无同令牌旧客户端、无本队在途任务，再启动工程入口；平台显示在线。仅此项不代表任务完成 |
| C05 | 有效通过 | 顺序运行一个可选官方任务并得到有效通过成绩。若平台只允许整批，则运行一个网站批次，记录全部结果，至少一项通过；失败不得只写“已完成” |
| C06 | 可审计 | 保存平台任务／run／批次标识、评分报告、可下载回放与本地版本；平台记录和本地日志能对应。未评分、中断、零分分别记录 |
| C07 | 工程交付 | 新环境按说明可运行；Git 提交包含源码、配置示例、许可证、版本清单与测试；无凭据、真实页面原文和运行资料 |
| C08 | GitHub | 新私有仓库创建并推送成功，远端 commit 与验收版本对应；保留链接。无法推送时标未完成，不能只交本地提交代替 |

官方任务以平台当时可选清单为准，不把旧文档的任务数当成当前事实，也不预写任务答案。失败先定位安装、协议、模型或执行问题，修复在本阶段范围内的接入错误；涉及新策略的实验先报告用户。

## 最终报告格式

将每批报告存到本阶段 `验收记录/`，实现开始时再创建。至少包含：

- 环境、命令、配置摘要、代码提交、SDK 与依赖版本。
- 上述编号的结果及证据路径；失败说明具体原因，未运行写未运行。
- 真实任务的输入、实际输出、操作记录、截图、时间与调用量。
- 改动与方案是否一致，尚需用户决定的事项。

第一阶段完成须 A 项通过、B 的后端选择确认且其余项通过、C 项通过。无需达到第二阶段能力或最终比赛完成率。最后交回可运行工程、GitHub 地址、运行说明和本阶段验收报告，等待用户决定下一阶段。
