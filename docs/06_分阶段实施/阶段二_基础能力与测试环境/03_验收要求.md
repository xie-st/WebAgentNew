# 第二阶段验收要求

状态：按 2026-10-31 用户确认的修订更新——新增 P 批（输入与核验生产接线），F/G 批范围收窄。实现以 [详细方案](01_详细方案.md) 和 [DSH 实施说明](02_DSH实施说明.md) 为准，任务定义见 [测试环境与任务](04_测试环境与任务.md)。

worker 完成离线与隔离网站验证；主线程执行获准的真实模型、官方平台和真实网站检查。每项分别写通过、失败或未执行，附命令与证据；不把调用次数或类型断言单独当作业务行为通过。**验收一律通过实际运行入口进行**：开关必须确实改变实际行为（捕获最终发送内容与实际核验／恢复事件证明），区分假模型契约与真实模型能力，不以模块测试通过替代生产路径验证。

| 编号 | 内容 | 通过条件 |

| P01 | 输入契约稳定 | 覆盖已有值、追加、多行、空文本回车与提交后取证均有确定性程序行为：空文本 type+submit 转为等价回车或显式拒绝，不再产生无反馈的平台动作；空文本 type 无 submit 被本地拒绝并回给模型明确错误；提交类动作后的观察自动留存截图／证据关联 |
| P02 | 官方 AX 适配 | 对官方观察，核验能按引号内名称匹配元素并从缩进子 StaticText 读取值；399 两批观察重放可区分错误追加值与正确替换值（旧批 obs-10 通过、新批 obs-5 拒绝） |
| P03 | 同循环纠错 | 完成核验拒绝在生成器结束前反馈，缺口条件进入同一循环继续纠正；假模型生产入口演示“错误追加→核验拒绝→继续纠正→通过”，不是只把终态改 incomplete |
| P04 | 行为开关 | 核验、状态工具、恢复各行为开关在官方入口实际生效：关闭时相应工具、提示词与钩子退出实际路径（捕获最终发送内容证明不再携带额外 schema），开启时事件记录实际启用情况 |
| P05 | 假／真模型区分 | 同一生产入口分别运行假模型与真实模型；假模型验证契约，真实模型验证自主使用；报告分列，不互相替代 |

P 批通过后才进入 R 波恢复／接管接线与 F/G 波。

## E 批：核验、恢复与接管（P 批后按 R 波接线）

| 编号 | 内容 | 通过条件 |
| --- | --- | --- |
| E01 | 核验结论 | pass/fail/unknown可区分；条件逐项检查；引用真实证据；语义核验用统一模型并计费 |
| E02 | 未知副作用 | L04中保存实际生效但反馈丢失时先取证，只保存一次；不能通过后台查库供Agent决策 |
| E03 | 局部恢复 | L05从最早有证据的错误处恢复；受影响依赖失效，无关已验证进度不重做；E1已verified目标的程序化失效入口可用；证据不足不编造因果 |
| E04 | 停滞 | 相同动作但有新证据不误判；无效循环触发受限恢复；恢复上限和截止时间真正生效 |
| E05 | 自动接管 | L06登录／验证提示触发全任务暂停，浏览器排空后交接；等待期间无新Agent动作 |
| E06 | 主动暂停 | L07取消旧提案；在途结果真实记录；继续重采集，不用旧编号，不伪造旧动作成功；E2反馈摄入与推进解耦，恢复使用新观察，避免多调用一轮旧观察提案后再丢弃 |
| E07 | 控制与计时 | 继续须有用户信号；取消可中断等待；总耗时、人工时间、执行时间可对账；官方deadline未被延长 |
| E08 | 重启 | 从完整快照加载并重观测；新分支与旧分支关联；模拟动作生效后进程中断，待确认记录仍在且不自动重发；不声称恢复生成器栈 |

E05／E06同时检查模型请求在暂停期间返回的情况：提案作废，但调用量和耗时仍计入。仅禁用UI按钮或打印“已暂停”不算通过。

E01还须覆盖提前结束：模型在只处理一部分对象后请求完成，完成检查应拒绝确认并返回剩余要求；同一循环继续，或以incomplete诚实结束，不能把部分进度记为整任务完成。

## F 批：并行、共享状态与限流（首版收窄：只读并行，共享写串行）

| F02 | 单页与共享写 | 每Tab最多一条在途动作；首版共享写任务一律串行执行（或明确拒绝并发），数据无覆盖丢失；细粒度共享写锁后置 |
| F03 | 动态依赖（后置） | 首版不要求计划修订与取消传播；对这类请求明确拒绝或串行执行，不得保留入口却无互斥／失效处理；实现后按原条件验收：L11计划修订后不再调度旧任务；旧结果归档；取消传播到依赖节点 |
| F04 | 统一限流 | L10两个分支共用节奏；429／冷却触发共同退避；等待可取消，恢复后不突发补发 |
| F05 | 模型与根预算 | 默认实际同时模型调用≤1；所有分支与规划核验共享根预算；失败、取消、被弃用结果也计费 |
| F06 | 官方退化 | 官方配置不暴露Tab工具，始终一个动作／请求、一个模型调用；真实端的串行模式也能执行同一计划 |
| F07 | 全局暂停 | 有多个分支、锁等待和限流等待时仍能排空与接管；未知写结果未核实前不能放开冲突写锁 |
| F08 | 容量与排队 | 默认串行；parallel未配置容量时取2，非法值报配置错误；就绪节点多于容量时，其余排队并最终执行；活跃数不超配置值；模型与站点限制不随分支数放宽 |
| F09 | 工作流选用 | 有原生WorkflowDAG对交互驱动、Tab、全局接管、动态计划和根预算的适用性验证及选用依据；选定路径通过F01–F08，不同时运行两套节点调度或重试逻辑；checkpoint未被当作生成器／页面恢复 |

F01以确定性延迟夹具和真实浏览器轨迹验证功能，不以假模型并发测试替代浏览器结果，也不在本阶段规定加速比。
