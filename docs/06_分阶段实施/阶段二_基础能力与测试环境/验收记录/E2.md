## 实现要点

### 1. 根控制状态与派发门

`ControlCoordinator` 维护任务级状态，不改 `SessionState` 含义。`request_pause` 一到即关闭派发门；`ControlState.RUNNING/REFRESHING` 才允许派发。`Session.consume` 调用同一门，因此即使调用方绕过受控循环也不能把动作交给后端。门测试见 `test_session_consume_gate_blocks_dispatch_while_paused`：暂停后 `session.consume` 抛 `ControlPaused`，提案仍在、无 in-flight、后端 0 执行、无 `dispatched` 事件。

### 2. 自动接管：先检测、后决定是否推进生成器

`ControlledLoopRunner` 在浏览器动作返回后先对返回的 `Observation` 做可见状态检测，再决定是否调用 `driver.accept_observation`。检测到登录/验证遮罩时：

1. `request_pause` 关闭门；`begin_drain` 记录已执行动作与反馈状态；
2. **不推进生成器**，把真实结果暂存（deferred feedback）；
3. 浏览器已无在途后端调用，`begin_user_control`，进入等待；
4. 只有显式 `resume` 到达后，才把暂存的真实结果交给生成器；若该轮用旧观察生成了提案，先 `Session.pause` 丢弃，再 `backend.observe()` 重观测并 `driver.resume(fresh)` 继续同一生成器。

这样等待窗口内没有模型调用、内部工具或页面动作。代价是恢复后多一轮基于旧观察的模型提案，该提案被明确记为 `proposal_dropped`/`not_executed`。共享驱动缺少“摄入反馈但不推进”的公开接口，需求见“共享集成文件需求”。

### 3. 主动暂停与继续

暂停发生在派发前时：门关闭后 `Session.pause` 丢弃旧提案，进入 `user_control`；显式 resume 后重观测，`driver.resume(fresh)` 以“NOT EXECUTED”把旧提案结果送回同一生成器。旧元素编号、旧 `observation_id` 不参与新动作；控制事件记录 `control_epoch/page_epoch`。

### 4. 计时与平台 deadline

`ControlTiming` 用单调时钟计算总时长，用显式 handoff 区间计算人工等待，执行时间 = 总时长 − 人工等待。平台截止时间在绑定 `Session` 时读取 `Deadline.epoch_seconds` 并存为只读原值；暂停不写 deadline。恢复前 `check_platform_deadline` 与 `Session.resume` 都会按原截止时间拒绝超期恢复。

### 5. 暂停期间模型结果

`ControlAwareModel` 是 EffGen `BaseModel` 包装器：`records_model_calls=True` 阻止驱动重复记占位；每轮 `generate` 用同一时钟测延迟并调用 `Session.record_model_call`（成功给离线合成 request id，失败不带平台 id），再写 `ControlCoordinator.record_model_result`。控制 epoch 变化时结果仍计数，但标记 `paused_at_return`/`proposal_usable=False`，其提案由 runner 丢弃且不产生 `dispatched/feedback`。

### 6. 重启

`restart_from_snapshot` 只调用 `StateStore.load`、`register_branch`、`pending_effects` 和新建 `EvidenceStore/Session`；启动新 run 的任务、重新观察一次，写独立控制事件。返回 `generator_restored=False`、`replayed_actions=()`，待确认副作用保持原状态。

## 偏离、限制与诚实披露

1. **deferred feedback**：E05 检测到遮罩后不调用 `driver.accept_observation`，以免产生反馈轮模型调用；真实结果延迟到显式 resume 后摄入。恢复时会多一次基于旧观察的模型提案，随后被丢弃并重观测。原因是 `effgen_bridge.py` 没有公开“摄入反馈但不推进生成器”的方法；按约束未改该文件，需求见下节。
2. **在途模型调用的边界**：若暂停请求发生在模型调用内部，该调用允许结束，提案丢弃、调用与延迟保留；若该轮返回的是内部工具而非外部提案，EffGen 会在该在途轮内执行内部工具。本批未修改桥接，故不能声称所有内部工具在“请求已发出但尚未返回”的边界上零执行；`user_control` 等待窗口内为零。
3. **Session 门位置**：门在 `consume`（派发）而非 `propose`。若门卡在 `propose`，暂停期间返回的模型提案会被 `_pump` 当格式错误纠正并追加模型调用，违背“提案作废、成本保留”。因此以“提案可记录、不可派发”为准。
4. **L06 遮罩变体**：清单默认启用登录遮罩；“验证遮罩”通过测试/证据脚本用同一 fault_id 替换故障类型实现，没有维护第二份 YAML。
5. **L06/L07 judge**：`testing/evaluation/judge.py` 属 D1，本批未改；测试通过 `LocalJudge._judge_l01` 复用同一检查体并自行写 `judge_result.json`。`prepared.judge()` 对 L06/L07 仍会因无分派方法而报错，需 D1 侧补别名。
6. **模拟用户**：离线用户动作通过 `PlaywrightBackend._page`（测试侧私有句柄）在 Agent 同一浏览器中完成登录/保存/导航；生产代码不依赖该私有字段。人工等待包含这些模拟动作耗时，不是实测真人时间。
7. **drain 超时**：后端 `execute` 是同步调用；动作超时/异常会转成 feedback error/exception，pending effect 记 failed/unknown。没有为并发后端实现独立 drain 计时器；本批无并发在途动作可超时。
8. **重启**：测试是进程内关闭/新 Session 加载，不是操作系统级 kill；未调用 E1 recovery，未恢复生成器栈，未重放动作。
9. **未运行**：真实模型、官方平台、公网真实网站、多分支全局暂停（F）未运行；本批通过率只覆盖离线本地/假时钟。
10. **计时精度**：本地真实浏览器运行的计时是 SystemClock 实测，只断言 `total=human+execution`（0.01 s）与 deadline 未变；精确 36/30/6 来自 FakeClock。

## 共享集成文件需求（本批未改）

1. **`effgen_bridge.py`（优先）**：增加公开的 `ingest_feedback_without_advance(observation)` 或 `resume_after_takeover(feedback_result, fresh_observation)`：
