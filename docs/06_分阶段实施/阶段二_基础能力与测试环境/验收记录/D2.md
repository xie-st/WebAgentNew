## 实现接口

- `TaskState`：`root_run_id`、`task`（用户任务原文）、`revision`、`plan_version`；`goals` / `facts` / `plan` / `pending_effects` 均按 ID 字典索引；依赖直接保存为 ID 元组。
- `Goal`：`goal_id`、要求、验收条件、依赖目标、对象范围、状态（pending/running/awaiting_verification/verified/blocked/invalidated/cancelled）、支持证据、分支、已完成对象 ID。
- `Fact`：`fact_id`、对象、字段/命题、值、observed/inferred、来源、有效性、修订号、证据、分支、可选目标归属。
- `PlanNode`：`node_id`、目标、依赖、输入事实、对象范围、资源声明、状态、计划版本、分支。
- `EvidenceRef`：证据 ID、run/branch 归属、相对路径、SHA-256、字节数、类型、observation/action 关联。`TaskState.validate` 与 `EvidenceResolver` 检查文件存在、字节数、哈希、run/branch 归属；损坏引用拒绝提交。
- `StateStore`：`initialize` / `load` / `apply_update` / `apply_plan_update` / `prepare_effect` / `confirm_effect` / `verify_goal` / `register_branch` / `verify_evidence`。
- `StateUpdate` / `PlanUpdate`：携带 `base_revision`、`plan_version`、`source_branch`；旧 revision 或旧 plan_version 抛 `StateConflict`，返回当前状态视图。
- 工具：`state_read`、`state_update`、`plan_update`；成功只表示快照已记录，不表示目标已核验。

| 事件日志与运行状态 | 第一阶段 `src/webagent/events.py`（`events.jsonl`、`run_status.json`） | 动作、反馈、模型调用诊断 | 沿用；D2 未改 | 诊断来源；不靠日志重放 TaskState |

新增账本字段的业务缺口依据：

- `EvidenceRef`：账本必须校验证据存在/哈希/归属，同时不在 JSON 里复制截图；缺口来自“账本只引用证据”。
- `branches`：分支证据归属与 run 目录对应，防止跨任务/跨分支引用；缺口来自并行分支与 D04/D07 归属检查。
- `Goal.completed_object_ids` 与 `object_progress()`：L02/L03 需要按不同对象计数，访问次数和重复证据不能凑数量；缺口来自“不同对象完整计数”。
- `PlanNode.resources`：F 批调度需要 Tab/账号/对象/共享写目标声明；本批仅保存与校验，不调度。
- `Fact.goal_id`：把事实关联到要求，支持对象计数与后续核验；可空，不强制每条事实属于目标。
- `PendingEffect.created_revision` / `updated_revision`：记录“发出前保存”的修订和反馈确认时的修订，支持重启后判断残留记录；缺口来自副作用不重发。
- `TaskState.updated_at`：快照审计时间；不是完成状态。
