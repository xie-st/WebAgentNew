# 第二阶段：基础能力与测试环境

状态：待审批。更新：2026-10-31。设计前提：第一阶段已完成验收与交接；本文不作为第一阶段实际完成记录。

## 目标与起点

第一阶段解决“能否运行”，本阶段解决“能否持续完成较长任务”：记住必要信息，确认操作结果，发现错误后保留有效进度，支持用户接管和多个页面协作。同时建好测试环境，让第三阶段可以逐项比较设计。

承接第一阶段最终交付：统一观察／动作协议、Session、证据存储、EffGen 可暂停循环、真实模型与浏览器接入、官方 SDK 接入。实际输入预算、执行失败反馈和模型用量记录已有验收证据。驱动的方法、配置和错误语义以最终交接版本为准。

实施前固定第一阶段最终提交、配置、后端选择和通过记录，并据此填写配套实施说明的接口映射。交接不满足上述前提时先补齐第一阶段。第二阶段在既有循环上增加能力，不另建 Agent 主循环，也不修改官方 SDK 通信层。

每项能力先对照交接版本的原生实现：可直接使用的沿用，能通过现有配置或扩展点满足的局部扩展，只有明确缺口才新增。轨迹、会话记忆、运行内压缩和业务任务状态分别确定职责；不按模块名称判断是否适用。具体对照与实施依据见[实施说明](02_DSH实施说明.md#effgen原生机制对照)。

## 能力安排

### 1. 状态账本

将任务拆成可核对的要求，记录对象、已知事实、缺失信息、未完成工作和证据。EffGen 决定怎么拆、如何推进；外围程序检查引用和状态转换，保存每次修订。

EffGen原生轨迹继续记录推理、动作和反馈；原生长期记忆用于通用记忆条目的存取。本账本只补完成核验、依赖失效、共享状态版本和待确认副作用，不另存一套对话历史，也不把同一完成状态同时交给两套记忆管理。

第一版用一个任务状态对象保存目标、事实、计划和未确认副作用，内部按 ID 用字典索引，依赖直接保存为 ID 列表。根协调器统一更新；每次有效更新后保存 JSON 快照，先写临时文件，再原子替换旧文件。重启加载最近完整快照并重新观察页面。截图、HTML和执行日志沿用第一阶段存储，账本只引用证据。

需要设计清楚的是状态、证据关系和旧结果处理。第一版不建数据库、不实现日志重放，也不单独维护依赖索引；执行记录复用已有日志，缺口由未满足条件推导。后续只有出现具体查询或存储瓶颈时才升级。

事实与推断分开。发出动作后先记“待确认”；观察和证据支持后才记“已确认”。切换页面、压缩历史或恢复任务时，仍然需要的对象值和已验证进度不能丢失。账本不保存可以拿来点击的旧页面编号。

### 2. 过程核验与恢复

在提交、保存、完成一个子目标及结束任务等节点核验结果。程序可直接检查的条件用程序检查；需要判断语义的条件交给统一模型，并保留依据。核验调用同样计入预算，默认不在每步另起一个核验 Agent。

失败后区分动作报错、结果不明、条件未满足、重复无效和方向偏离。优先定位最早有证据表明出错的节点；证据不足时保留未知，不强行归因。只撤回依赖该节点的完成判断，保留无关的已确认结果，再由 EffGen 调整计划。

带业务副作用的动作在超时后不能直接重发。先检查页面上的实际结果，再决定继续或重试。反思只记录有反馈依据的原因与修正办法，作为本任务内提示；不自动转成跨任务 skill。

### 3. 用户接管

真实端识别登录、验证码、二次验证及用户主动暂停，停止发出新动作。等待在途操作结束或明确记录结果不明后，才交出浏览器。

用户完成后确认继续，重新获取所有受影响页面的观察，使旧编号、未执行动作和失效会话假设作废，再恢复任务。保留已确认的业务结果，不清空全部历史。默认全任务暂停，避免其他 Tab 在用户操作期间继续改动共享状态。

记录接管起止和恢复结果。真实端同时报告总耗时、人工时间和有效执行时间；官方任务截止时间仍以服务器为准，不能由本地暂停延长。

### 4. 多 Tab 调度与限流

EffGen 识别任务依赖和可并行部分，生成或修订任务图。实施F批前先核对原生WorkflowDAG能否承接可暂停驱动、页面归属、根预算与全局接管；适用部分优先复用，缺口由轻量协调器补充，不因已有DAG就直接套用整套工作流。每个执行分支拥有独立的循环、Session、Tab 和观察；程序只调度前置条件已满足、资源没有冲突的任务，共享账本通过带版本的更新合并。

默认串行；开启并行后，`max_active_branches`默认2，可调为3、4或更多，不设2分支硬上限。调度器按就绪任务、配置容量、可用页面和资源约束启动分支，其余排队。每个 Tab 最多1个在途动作，模型并发初始为1，站点访问节奏独立限制。

2是低资源开销的初始配置，用于启用并行，不代表最佳值。更多分支能重叠网页等待，也会分摊模型调用、预算和浏览器资源；第三阶段再比较容量收益。

共享账号、购物车、目标对象或写入位置时加相应约束；不能只因 URL 不同就判断独立。计划改变后，旧任务返回的结果先归档，重新核对后才能写入当前进度。

真实端共用域名级访问节奏和退避状态，分支不能分别限流后把总频率翻倍。初始配置为每站点每秒最多发起1次 Agent 导致的页面操作，突发量1，并结合站点规则调整；这是保守起点，不代表网站公布的限额。遇到冷却或挑战先降速、暂停或接管，不继续试探。浏览器自身资源加载另行观测，不把一次点击等同于一个网络请求。

官方端保持单任务、单动作与单模型调用约束，不开放多 Tab。真实端的同一调度图能切换串行运行，为第三阶段保留对照。

### 5. 上下文和观察处理

复用EffGen的AgentThread、原生预算与压缩策略入口，向其中加入完整当前AX、必要账本和近期行动；不另建一套轨迹或在外围再次截断已压缩历史。项目侧保留最终输入及官方字节／消息限制检查。

在这一入口上提供三个独立选项：同轮短摘要、旧观察差分、已完成子目标折叠。当前页不使用差分代替原文，原始日志始终保留。跨任务记忆关闭不代表运行内压缩关闭；基线须记录实际策略与预算。项目选项默认关闭，原生必要压缩仍按明确配置执行。

DOM 筛选做成独立选项：EffGen 提供关键词和权重，固定程序评分。候选必须能可靠对应当前可操作元素；不能映射的 DOM 节点只作信息，不能生成动作编号。筛选后找不到目标时允许扩大候选或返回 AX。

这些能力在本阶段证明可运行、可开关、不破坏数据和协议；是否改善完成率、时间和成本由第三阶段实验决定。默认配置先关闭三种历史优化、DOM 任务相关筛选和经验检索。

### 6. 经验与 skill

账本、核验和恢复完成后，再提供通用经验的格式、读取和适用性检查。本地EffGen核心源码未发现独立skill加载执行系统，已有工具注册和工作流机制；优先用现有接口承载文本指导与网页动作，只补经验的适用条件、批准版本和有界执行约束，不另建工具运行时。第一版经验库为空，不接外部检索或 embedding 服务。可加载人工批准的文本指导，以及由现有网页原语和核验节点组成的有限动作组合。

skill 不含特定任务答案、已过期元素编号或隐藏网站接口。组合动作在官方端仍逐个交出、接回观察；真实端也不绕过渲染与实际操作。教师出题、自动提炼经验和轨迹裁剪均留到第三阶段逐批审批。

## 测试环境

采用本地浏览器网站、官方调测和公开真实网站三层。

本地网站包含论坛式表单、商品检索与比较、长列表、草稿和多页面任务，支持改变数据、布局及故障时机。浏览器只通过页面做任务，判定器在外部读取测试状态。假模型用于协议与调度测试，真实统一模型用于端到端验证，两类结果分开。

真实网站以赛方小红书案例为主：从搜索结果中找到至少20个不同、相对中性或正向的相关帖子；逐一编辑包含文字和表情的感谢评论，截图后取消，不发送。每条都要完成整套步骤，不能只累计浏览过的帖子。具体任务参数从任务文件读取，不写死网站答案。

详细清单、重置与判定见 [测试环境与任务](04_测试环境与任务.md)。真实网站需要用户登录时走接管流程。样本无法凑足或页面不可访问时记录实际数量与原因，不能补造完成证据。

## 分四批实施

| 批次 | 工作 | 交付 |
| --- | --- | --- |
| D | 对齐第一阶段；测试框架、账本、任务与证据关系 | 可保存、加载的任务状态和第一组本地任务 |
| E | 核验、恢复、自动接管与继续 | 错误分类、局部恢复及接管证据 |
| F | 多 Tab、任务图、共享状态与限流 | 串行／并行两种执行方式，调度轨迹 |
| G | 上下文选项、DOM 筛选、经验加载；三层联调 | 开关配置、固定任务清单、基线结果 |

批次验收按D→E→F→G交回，逐批等待反馈。开发可利用局部重叠：D的账本接口稳定后可支持已获批的E任务；F的独立限流、就绪队列可与E重叠开发，完整调度集成仍依赖账本和接管接口。批内测试环境与账本、核验恢复与接管、上下文处理与经验模块可分别开发，公共文件统一集成。不为开发并行改变架构，出现强依赖就顺序做，不提前执行未批准任务。进入第三阶段前冻结代码、配置和任务清单。第二阶段验收只证明能力符合契约，不提前宣称某项设计有效。
