## 二、设计变量

统一定义 CSS 变量，组件直接复用；不在各区域自行选择一套颜色、圆角和间距。

| 项目 | 取值与用途 |
| --- | --- |
| 页面背景 | `#F4F7FB`，与白色内容面板拉开层次 |
| 内容表面 | `#FFFFFF`，任务编辑、执行预览、结果区域 |
| 主文字 | `#192838`，标题、输入、回答 |
| 次文字 | `#59687A`，说明、时间、辅助信息 |
| 品牌蓝 | `#3B78C3`，沿用 PPT 蓝色，用于边线、图形点缀 |
| 操作蓝 | `#2D64A6`，主按钮与文字链接；白字按钮和小字号链接使用此色并实测对比度 |
| 分隔线 | `#D8E0EB`，区域边界与表单边框 |
| 状态色 | 成功深绿 `#216447`、等待／暂停深棕 `#855C18`、失败深红 `#A62D35`；淡底上用深色文字并实测对比度，颜色旁始终有状态名称 |

字体使用本机可用的 `"Segoe UI Variable", "Segoe UI", "Microsoft YaHei UI", "Microsoft YaHei", sans-serif`；日志与 ID 可使用 `Consolas, monospace`。不下载网络字体，不依赖 CDN 资源。

字号以正文 16px 为基准：主标题 24–28px，区域标题 18–20px，辅助文字 14px；日志 13–14px，时间等次要元信息可用 12–13px。任务输入与最终回答不得缩成小字。正文行高 1.6，长回答限定合理行宽并保留段落。

间距使用 4／8／12／16／24／32px；桌面外边距 24–32px，区域间距 20–24px。输入框与按钮高度至少 40px；键盘焦点有清晰的 2px 蓝色轮廓。表单圆角 6px，主体容器 10px，状态标记可用胶囊形；不同层级保持一致。主体靠留白、底色与细线分区，避免所有区域都叠加明显阴影。

## 三、布局与视觉重心

顶部只保留项目名称“WebAgent 演示”、一句用途说明、当前模式与运行状态。页面主体最大宽度约 1600px，居中放置。主内容左对齐。

桌面左栏约 320–360px，提供任务输入和控制；右侧占其余宽度。右侧上半部按约 60%／40% 展示浏览器截图和回答，下半部是紧凑事件日志。截图与回答同属执行工作区，避免把每个统计字段拆成同等大小的卡片。

```text
WebAgent 演示                        真实模型   运行中
输入任务，查看真实浏览器执行与结果
──────────────────────────────────────────────────────
任务与操作             执行工作区
┌─────────────────┐   ┌──────────────────┬─────────────┐
│ 任务描述         │   │ 真实页面预览      │ 回答与结果   │
│ 多行输入框       │   │ URL / 最近动作   │ 完成情况     │
│                 │   │                  │             │
│ 起始网址         │   │ 浏览器实际截图    │ 最终回答     │
│ 模式 / 时间      │   │                  │             │
│ 开始运行         │   ├──────────────────┴─────────────┤
│ 暂停 继续 取消   │   │ 事件日志                         │
│ 高级配置（折叠） │   │ 动作 → 页面反馈 → 下一步          │
└─────────────────┘   └────────────────────────────────┘
                      运行记录 / 下载证据
```

任务输入框初始约 5–7 行，允许纵向调整；使用真实任务内容而非大段装饰文案。运行时任务保留，明确当前执行的是哪份输入。主要执行信息在 1366×768、100% 缩放下即可看到；长日志在自身区域滚动，不把运行按钮和结果挤到页面深处。

右侧截图使用 `object-fit: contain`，保留原始长宽比，不裁掉任务证据。窗口形外框可以承载 URL，但不绘制虚假的浏览器控件。点开原图看细节，截图缩略图列表放在次级位置。

在约 1100px 以下，右侧截图与回答可上下排列；约 900px 以下主体改为单列。390px 窄屏顺序为任务与控制、状态、结果、截图、日志；按钮允许换行。页面不出现横向滚动，长 URL、run_id、文件路径允许折行或提供局部滚动。

## 四、状态设计

| 状态 | 画面应表达什么 |
| --- | --- |
| 待运行 | 输入框可用，开始按钮突出；截图区写“运行后显示真实页面截图”，结果区提示输入任务；不放假数据 |
| 启动／运行中 | 状态名称、已用时间、最近实际动作；还没有截图时保留稳定预览框并说明等待；不用虚构完成百分比 |
| 暂停请求中 | 显示“等待当前操作结束”；暂不指示用户接管；按钮防重复提交 |
| 已暂停 | 清楚显示“已暂停，可以在浏览器中操作”，继续按钮成为主要操作 |
| 完成 | 回答正文优先，证据与结束原因就近可查；成功含义严格沿用开发文稿的核验口径 |
| 未完成／失败 | 显示已完成的实际进度、结束原因与现有证据；输入和再次运行入口易于找到 |

开始／暂停／继续保持相同的动词用法。取消作为次要危险操作，强制结束放在需要时展开的位置；避免多个醒目主按钮争夺注意力。

日志新增不让整页闪烁或跳到页面顶部；用户正在阅读旧日志时保留滚动位置，可提示有新消息。复制、下载给出简短反馈。状态变化最多使用约 120–180ms 的轻微过渡；关闭系统动画时取消非必要动效。

## 五、实施与视觉复核

接收窗口派发前，将上述设计变量和布局纳入任务；worker 开始界面实现前核对项目用途与真实内容，避免先搭默认表单、交付前再随意“美化”。仍使用已确定的原生 HTML/CSS/JS，视觉要求不引入 React、图标库或打包链。

worker 完成后运行页面，用实际浏览器截图自查；接收窗口再打开截图做独立复核，不另建评审 agent。至少检查以下内容：

1. 1366×768、1920×1080 的完整视口初始页与完成页，使用真实长度的任务和回答。
2. 运行中、已暂停、失败／未完成状态；完成页必须使用可追溯的实际 run。
3. 390px 窄屏与桌面 125% 缩放；输入、操作、结果可找到，没有遮挡与溢出。
4. 键盘焦点、文字对比度、禁用态、长 URL、长日志、缺失截图与减少动效设置。

画面检查重点是：任务与结果的主次是否一眼可辨，实际截图是否足够大，中文是否容易阅读，各区域是否对齐，留白是否一致，状态是否清楚。发现问题记录“位置、问题、修改”，修改后对同尺寸、同状态重新截图；无问题时记录实际核对依据。

保存到 `验收记录/<批次>/自验证截图/视觉/`，命名包含尺寸和状态，例如 `1366x768_完成.png`。在验收记录注明截图的窗口尺寸、浏览器缩放、代码版本及关联 run_id；使用完整视口图，不能通过裁剪隐藏布局问题。交付者须实际查看图片，不能仅检查图片文件存在。

本轮只补充规范和验收，不将设计文稿或功能测试计为成品视觉通过。最终按 D17–D20 复核，发现明显的截断、遮挡、层级混乱、文字难读或内容拥挤，修正后再交付。
