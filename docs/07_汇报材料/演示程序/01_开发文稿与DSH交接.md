## 一、目标与演示方式

做一个本机运行的中文演示面板。操作人打开页面，填写任务、起始网址，点击“开始运行”；Agent 在可见的真实浏览器中操作，面板持续显示执行状态、动作日志、最终回答与页面截图。输入任务无需手工编辑 JSON，暂停、继续、取消无需另开终端写控制文件。

演示流程：启动一次程序 → 页面输入任务 → 开始运行 → 观看真实浏览器和面板输出 → 查看结果与截图 → 开始下一项任务。

默认只运行一个任务，沿用现有 EffGen 循环、Playwright 后端、配置和证据格式。它是现有工程的演示入口。

### 方案选择

| 方式 | 实际代价 | 采用情况 |
| --- | --- | --- |
| 继续使用 CLI | 改动最少，但临场需要编辑任务文件和控制命令 | 作为底层执行入口 |
| 本地网页面板调用 CLI 子进程 | 复用完整执行链，输入与输出集中展示，可隔离任务进程 | **本次采用** |
| 新增桌面应用、前端构建工程或重写 Agent 循环 | 引入额外打包和集成工作 | 本次不安排 |

采用 Python 标准库本地 HTTP 服务、原生 HTML/CSS/JS 与短轮询；不新增前端构建步骤。新增依赖确有必要时，由接收窗口结合现有环境决定并记录。

## 二、页面需求

页面宽屏下一屏能看到任务输入、运行状态和主要输出；日志、截图使用各自的滚动区域。中文标签清楚，优先保证现场可读。

视觉按[视觉设计与验收](03_视觉设计与验收.md)执行：沿用现有 PPT 的白底、蓝色重点与清晰分隔，采用左侧任务操作、右侧截图与结果的工作台布局。颜色、字体、间距、各状态与截图复核均有明确要求；美观与功能一起验收，不能只交默认表单皮肤。该要求依据用户本轮“参考相关 skill、保障美观”的补充纳入。

| 区域 | 必需内容与行为 |
| --- | --- |
| 输入 | 多行“任务描述”、独立“起始网址”、正数“最长运行秒数”；保留最近输入便于修改重跑 |
| 模式 | “真实模型”与“离线脚本演示”，当前模式始终可见；默认真实模型，缺少配置时提示原因 |
| 预设 | “本地目录检索与草稿预览”一键填入；真实模型模式下任务可编辑 |
| 操作 | 开始运行、暂停、继续、取消；按钮随实际状态启用，运行中禁止再次启动 |
| 状态 | run_id、运行模式、开始时间、已用时间、执行状态、当前页面 URL、最近动作；缺少数据时显示“暂无” |
| 结果 | 最终回答、终止原因、本地核验情况；与日志分区，回答可直接复制 |
| 过程 | 持续追加动作、反馈、暂停和异常日志；默认展示与演示相关的内容，可展开完整脱敏日志 |
| 截图 | 最新真实页面截图与本次截图列表，点击可放大；标注所属 run_id 与观察标识／文件名 |
| 证据 | 下载本次任务输入、结果 JSON、执行日志、截图；显示运行目录绝对路径 |

高级配置折叠展示配置文件位置与实际模型名。密钥只从现有环境变量读取，不放进任务输入区或网页持久化存储。

页面状态至少包含：待运行、启动中、运行中、暂停请求中、已暂停、继续请求中、取消请求中、已结束。结束后分别显示完成、未完成、失败、超时、已取消；启动失败也必须有可见结论。

## 三、接入既有工程

### 执行链

```text
本地演示面板
  → 校验输入，生成独立 task.json 与 run_id
  → 启动现有 python -m webagent run 子进程
  → EffGen + harness + Playwright 实际执行
  → 读取 stdout/stderr、events.jsonl、result.json、screenshots/
  → 更新面板并提供本次证据下载
```

服务绑定 `127.0.0.1`。HTTP 请求线程只负责快速应答，运行和读取输出放后台；任务未结束时面板仍可刷新、查看状态、提交控制请求。同一服务通过锁保护一个活动 run，连续点击和多浏览器标签页都不能绕过。

子进程使用当前 `sys.executable`、参数列表及 `shell=False`；固定仓库根目录为 cwd。任务文本写 UTF-8 JSON，不拼入 shell 命令。设 `PYTHONUTF8=1`、无缓冲输出，正确保留中文、换行、引号和表情。

拟交付启动命令如下，开发后必须实测；这是待实现入口：

```powershell
Set-Location D:\Dwen\Alpha26fall\WebAgentNew
.\.venv\Scripts\python.exe code\harness\demo\app.py --port 8787
```

服务启动后自动打开 `http://127.0.0.1:8787`；自动打开失败时终端保留可点击地址。端口占用则明确报告并允许用 `--port` 更换，不停止占用端口的其他程序。可附 `start_demo.ps1`，但上述 Python 命令必须能独立使用。

真实运行复用当前 CLI，参数由程序生成，例如：

```text
<当前Python> -u -m webagent run
  --config <仓库>/code/harness/configs/real.yaml
  --backend playwright
  --task-file <本次演示输入目录>/task.json
  --run-id <新run_id>
  --runtime-dir <仓库>/runtime
  --no-headless
  --max-seconds <页面输入的正数>
```

实际启动使用参数列表，上述换行仅便于阅读。真实模型读取 `WEBAGENT_MODEL_BASE_URL`、`WEBAGENT_MODEL_API_KEY` 及现有配置模型名。缺失密钥时真实模式应在启动前提示；离线模式仍可使用。`doctor` 可辅助检查，但其总结果不能代替逐项检查，因为当前部分环境变量／浏览器检查是非致命项。

### 已核对的复用点

以下路径均相对于仓库根目录；接收窗口开发前复核当时版本。

| 文件／目录 | 当前用途与接入办法 |
| --- | --- |
| `code/harness/src/webagent/cli.py` | `run` 接受任务 JSON、网址、run_id、时限、`--no-headless`、`--model-script`；本次优先直接复用 |
| `code/harness/configs/real.yaml` | 真实端配置与模型环境变量名；界面不擅自启用新机制 |
| `code/harness/src/webagent/control/file_control.py` | 每行 `pause`／`resume`／`cancel` 的控制协议 |
| `runtime/runs/<run_id>/control.jsonl` | 追加控制命令的位置；由本次实际运行创建后使用 |
| `runtime/runs/<run_id>/events.jsonl` | 观察、动作、反馈等结构化事件；按真实字段映射，不创造不存在的字段 |
| `runtime/runs/<run_id>/result.json` | 终态与回答；当前有 `termination`、`finish.message`、`finish.claim`、`summary`、`last_observation` 等字段 |
| `runtime/runs/<run_id>/screenshots/` | 真实浏览器产生的截图；用对应观察记录关联 URL 和对象 |
| `code/harness/tests/fixtures/site/` | 已有静态目录、搜索、详情、草稿预览网站 |
| `code/harness/tests/fixtures/tasks/local_chain.json` | 已有可重复本地任务模板 |
| `code/harness/tests/fixtures/fake_scripts/local_chain.json` | 固定 quantum 查询与固定草稿的脚本模型响应 |

结果区优先读取真实 `finish.message`，其次 `finish.claim`，保留原始 result.json 供核对。回答缺失时显示“未返回最终回答”，同时展示终止原因与已有进度，不以最后一条动作日志代替回答。当前字段不够用时，先从已有事件查找，仍无法满足才由接收窗口做最小集成修改。

### 控制语义

点击暂停只是提交暂停请求。收到 CLI 的 `PAUSED` 或等价结构化确认后，才显示“已暂停，可以接管”。CLI 当前在动作之间处理命令，模型调用或网页动作进行中不能承诺立即停止。

暂停后用户在可见浏览器中手工操作；点击继续后，等待 CLI 重新观察页面并确认恢复，再显示“运行中”。旧动作和旧元素编号按现有驱动失效，不在面板侧重发。

取消同样先显示请求中；以进程结束及真实终态确认最终状态。若子进程无响应，提供明确的“强制结束本次任务”操作，只清理本面板启动的进程树；强制结束记为中断，保留已有证据，不伪造正常 result.json。

刷新面板重新绑定当前活动 run，不启动新任务。取消请求中仍禁止新运行；旧进程退出并完成归档后才释放运行锁。关闭服务时清理其拥有的执行进程和浏览器，不影响其他窗口运行的测试／官方连接。

### 展示与记录规则

- 区分“Agent 返回完成”“本地核验通过”“官方评分”。现有真实 CLI 未提供核验证据时显示“未提供本地核验结果”，不凭回答文字打绿色通过标记。
- 进程退出码、result.json 和日志共同呈现；启动错误、非正常退出、文件缺失不能显示完成。文件尚在写入或 JSONL 尾行不完整时稍后重读，不能让面板崩溃。
- 日志、回答和任务按纯文本渲染；仅提供本服务已登记运行目录中的允许文件，不接受任意路径读取。
- 保留原有日志脱敏，并检查新增 stdout/stderr 展示和下载内容；不把密钥、官方连接文件或浏览器 profile 打包。
- 本次不增加官方评测启动入口，不切换其他窗口的运行版本，不用面板改写官方成绩。

## 四、两种演示模式

### 真实模型：主要演示

任务与网址自由输入，实际调用已配置模型，启动可见 Chromium，展示真实网页变化与输出。预设默认使用仓库已有本地目录站点，避免临场输入重复劳动；也能输入其他 HTTP(S) 网址。

服务直接把既有 fixture 作为 `/fixture/` 静态路径提供，无需用户另开 `http.server`。使用对应端口的起始网址：

```text
http://127.0.0.1:<面板端口>/fixture/index.html?seed=alpha-17
```

预设任务可写成：搜索 quantum，打开第一条结果，在草稿框输入 `Draft for quantum note`，点击预览，确认预览文字并保存截图，不提交。输出检查以页面预览、动作日志和截图为依据；真实模型自行选择动作。

### 离线脚本：无密钥排练

沿用同一 CLI、EffGen 循环和可见 Playwright 浏览器，只增加已有 `--model-script`。页面始终显示“离线脚本演示：固定响应，未调用真实模型”。该模式仅允许执行与脚本匹配的固定本地预设，锁定任务和网址；切回真实模式后恢复编辑。

不能让用户修改任务后仍执行固定 quantum 脚本并称为处理了新任务。示例脚本响应中的“已截图”声明也不替代真实截图文件检查。每次运行使用新 run_id，重新打开干净的本地预设页面。
