# 第二阶段验收要求

状态：待审批。实现以 [详细方案](01_详细方案.md) 和 [DSH 实施说明](02_DSH实施说明.md) 为准，任务定义见 [测试环境与任务](04_测试环境与任务.md)。

worker 完成离线与隔离网站验证；主线程执行获准的真实模型、官方平台和真实网站检查。每项分别写通过、失败或未执行，附命令与证据；不把调用次数或类型断言单独当作业务行为通过。

## D 批：交接、测试环境与账本

| 编号 | 内容 | 通过条件 |
| --- | --- | --- |
| D01 | 第一阶段交接 | 最终代码／配置、后端与验收证据齐全；预算、错误反馈、模型用量缺口有明确归属；未通过真实接入不得记通过 |
| D02 | 测试隔离 | 网站确实渲染；每次独立数据副本；Agent 看不到判定接口、隐藏答案和故障真值；相同seed可重置 |
| D03 | 事实与确认 | 拟执行动作不能增加 verified；observed不等于成功；缺证据、跨任务证据、坏哈希被拒绝；推断与观察事实分开 |
| D04 | 事务与重放 | 中断更新不留下半次事务；日志重放一致；新旧修订冲突不丢数据，旧版本仍可查 |
| D05 | 目标完整性 | 不遗漏用户要求；计划无环；未完成要求不能被模型删除；L02按不同对象完整计数 |
| D06 | 长任务 | L01／L03保留对象、关键值和每条证据；20条须逐条完成编辑—截图—取消，提交计数为0 |

## E 批：核验、恢复与接管

| 编号 | 内容 | 通过条件 |
| --- | --- | --- |
| E01 | 核验结论 | pass/fail/unknown可区分；条件逐项检查；引用真实证据；语义核验用统一模型并计费 |
| E02 | 未知副作用 | L04中保存实际生效但反馈丢失时先取证，只保存一次；不能通过后台查库供Agent决策 |
| E03 | 局部恢复 | L05从最早有证据的错误处恢复；受影响依赖失效，无关已验证进度不重做；证据不足不编造因果 |
| E04 | 停滞 | 相同动作但有新证据不误判；无效循环触发受限恢复；恢复上限和截止时间真正生效 |
| E05 | 自动接管 | L06登录／验证提示触发全任务暂停，浏览器排空后交接；等待期间无新Agent动作 |
| E06 | 主动暂停 | L07取消旧提案；在途结果真实记录；继续重采集，不用旧编号，不伪造旧动作成功 |
| E07 | 控制与计时 | 继续须有用户信号；取消可中断等待；总耗时、人工时间、执行时间可对账；官方deadline未被延长 |
| E08 | 重启 | 可重放账本并重观测；新分支与旧分支关联；不自动重发未知写操作，不声称恢复生成器栈 |

E05／E06同时检查模型请求在暂停期间返回的情况：提案作废，但调用量和耗时仍计入。仅禁用UI按钮或打印“已暂停”不算通过。

E01还须覆盖提前结束：模型在只处理一部分对象后请求完成，完成检查应拒绝确认并返回剩余要求；同一循环继续，或以incomplete诚实结束，不能把部分进度记为整任务完成。

## F 批：并行、共享状态与限流

| 编号 | 内容 | 通过条件 |
| --- | --- | --- |
| F01 | 真实并行 | L08有两条独立浏览器等待的时间重叠；每分支使用独立循环与Tab，原件归属不串；不是仅切页演示 |
| F02 | 单页与共享写 | 每Tab最多一条在途动作；L09共享写串行，数据无覆盖丢失；锁顺序无死锁 |
| F03 | 动态依赖 | L11计划修订后不再调度旧任务；旧结果归档，不覆盖新状态；取消传播到依赖节点 |
| F04 | 统一限流 | L10两个分支共用节奏；429／冷却触发共同退避；等待可取消，恢复后不突发补发 |
| F05 | 模型与根预算 | 默认实际同时模型调用≤1；所有分支与规划核验共享根预算；失败、取消、被弃用结果也计费 |
| F06 | 官方退化 | 官方配置不暴露Tab工具，始终一个动作／请求、一个模型调用；真实端的串行模式也能执行同一计划 |
| F07 | 全局暂停 | 有多个分支、锁等待和限流等待时仍能排空与接管；未知写结果未核实前不能放开冲突写锁 |

F01以确定性延迟夹具和真实浏览器轨迹验证功能，不以假模型并发测试替代浏览器结果，也不在本阶段规定加速比。
