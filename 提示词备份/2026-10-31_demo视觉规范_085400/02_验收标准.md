# 演示程序验收标准

日期：2026-10-31。状态：待执行。对应[开发文稿与 DSH 交接](01_开发文稿与DSH交接.md)。

核心交付目标：操作人用一条命令启动，直接输入任务和网址，看到真实浏览器执行、持续日志、最终回答和真实截图；能在同一页面控制运行并导出证据。

以下 D01–D16 均为核心项。通过、失败、未执行分别记录；“待执行”不能写成通过。离线测试、真实模型验收、官方成绩分别保留。

## 一、功能与可用性

| 编号 | 如何验收 | 通过条件 |
| --- | --- | --- |
| D01 启动 | 仓库根目录按 README 执行一次启动命令；再检查端口占用场景 | 自动或点击终端地址打开中文面板，不需另启前端构建或 fixture 服务；占用时有明确提示，换端口后预设网址同步正确 |
| D02 方便输入 | 填写中文、多行、引号和表情的任务及 HTTP(S) 网址；修改后再次启动 | 无需编辑 JSON；实际生成任务与输入逐字对应，UTF-8 正确；真实模式任务和网址可自由编辑 |
| D03 输入检查 | 分别提交空任务、空／非法网址、非正数时限；真实模式缺少模型配置 | 面板直接显示可理解的错误，不启动运行进程；离线模式不因无密钥被阻断 |
| D04 单任务隔离 | 双击开始；另一个标签页同时开始；结束后再运行一次 | 同时最多一个活动任务进程；后续运行有新 run_id、独立目录；不覆盖旧输入、日志和截图 |
| D05 离线演示 | 无模型密钥，选择固定本地预设并连续运行两次 | 均通过现有 CLI、EffGen 和可见 Chromium 完成搜索、详情、草稿预览；页面始终标注脚本模式；任务和网址锁定；真实模式仍可编辑 |
| D06 真实模型 | 用实际配置模型执行一次本地预设，再提交一个不同任务，至少一次含中文 | 保留真实模型调用记录；任务修改确实传入执行链；可见浏览器完成操作；面板展示对应回答与页面证据；没有静默使用脚本响应 |
| D07 过程可见 | 运行期间观察面板，对照子进程与原始日志 | 开始后及时显示 run_id 和状态；已有日志产生后通常 2 秒内更新；动作、反馈、当前 URL 可核对；模型等待中界面仍可响应 |
| D08 最终输出 | 对照 result.json 与页面结果区，覆盖完成和未完成两种终态 | 回答、终止原因、run_id 一致；没有回答明确显示缺失；模型自报完成不自动等于本地核验或官方通过；运行计时在结束后停止 |
| D09 截图 | 完成任务后放大／下载最新截图，再运行下一任务 | 截图来自实际浏览器，可查看原图；预览中能看见对应草稿文字；文件与当前 run_id、观察归属对应，不串用上次截图 |
| D10 证据下载 | 在面板下载本次输入、结果、日志、截图，与原件对照 | 文件可打开且内容对应；显示可定位的绝对目录；强制中断缺少终态时仍可下载已有证据；不混入其他运行或凭据文件 |

D06 的第二个任务可使用同一 fixture，改查询词或要求读取不同页面内容；必须让真实模型据新任务产生动作，不能依靠更换展示文字通过验收。正常完成的真实模型运行至少一条完整满足输入中的业务要求。

## 二、控制与故障

| 编号 | 如何验收 | 通过条件 |
| --- | --- | --- |
| D11 暂停与继续 | 在有足够操作步骤的本地任务中点击暂停；确认后手工改变浏览器页面，再继续 | 请求中与已暂停分开；确认已暂停后无新 Agent 网页动作；继续触发重新观察，旧提案／编号失效；沿原任务继续；按钮与实际状态一致 |
| D12 取消与清理 | 运行中、暂停中分别取消；模拟无响应后强制结束；最后关闭服务 | 取消确认前不放开新任务；取消后没有遗留本次执行进程；强杀显示中断并保留原件；只清理本面板拥有的子进程，其他窗口服务不受影响 |
| D13 异常与刷新 | 模拟模型不可达／子进程启动失败、读取部分 JSONL、结果缺失，并在运行中刷新面板 | 明确显示原因，不假报成功；读文件暂不完整可重试；刷新恢复当前 run 和日志，不重复启动；异常结束后可再次使用 |
| D14 内容与文件处理 | 输入含 HTML 标签、shell 特殊字符的任务，检查新增界面／下载代码，尝试访问登记目录以外文件 | 输入按文本显示并原样写任务，不执行 shell／HTML；下载只限本次登记产物；日志与下载不含实际 API key、连接令牌或浏览器 profile |
| D15 工程回归 | 在最终集成版本运行 demo 测试和现有 harness 离线回归，核对导入路径 | demo 的进程锁、控制确认、结果映射、模式隔离有行为证据；原有必要回归通过；有修改公共文件时补对应回归；失败不得只交 worker 自报通过 |
| D16 交付复现 | 另一终端按说明重启程序，依次打开自验证截图和证据索引 | 启动命令可复现；代码、说明、模式标识、测试结果截图、面板结果图、真实网页截图齐全；版本／文件哈希与最终被测代码对应 |

暂停、取消测试可使用可控的延迟假模型／子进程验证请求中状态，再用真实浏览器验证暂停后接管与恢复。不要以预录页面动画替代执行证据。取消在动作边界处理，允许展示等待，但必须有无响应时结束本次进程的办法。

## 三、自验证证据

在本目录下新建 `验收记录/<批次>/`，记录实际命令、起止时间、代码版本／工作区差异清单与文件哈希、配置、依赖、导入路径、run_id 和逐项结论。原始运行数据保留在 `runtime/`，共享交付通过证据索引对应；用于交付的脱敏证据副本放入该批次目录。

最少准备以下截图；图片必须是实际执行结果：

| 文件建议名 | 截图内容 |
| --- | --- |
| `自验证截图/01_测试结果.png` | 可见执行命令、测试摘要、通过／失败数量的真实终端画面；长输出可拆成多张 |
| `自验证截图/02_离线完成.png` | 当前模式、run_id、终态、回答和截图预览 |
| `自验证截图/03_真实模型完成.png` | 真实模型模式、任务、run_id、实际回答和证据入口 |
| `自验证截图/04_浏览器预览.png` | 真实浏览器中生成的草稿预览；能与同次运行日志关联 |
| `自验证截图/05_暂停接管.png` | 已暂停的确认状态与可见浏览器；配套日志证明继续后重新观察 |
| `自验证截图/06_异常反馈.png` | 一次真实触发的输入或启动异常，及明确原因 |

测试截图证明自验证执行情况；面板与浏览器截图证明演示流程，三者分别保留。截图中避免暴露凭据。仅增加截图数量或粘贴“通过”文字不能替代原始日志。

建议由实现提供一条 demo 专项验证命令；交回时必须填写其真实命令，不能只写“测试通过”。完整 harness 回归可沿用仓库 README：

```powershell
Set-Location D:\Dwen\Alpha26fall\WebAgentNew
$env:PYTHONUTF8 = '1'
.\.venv\Scripts\python.exe -m pytest code\harness\tests -q
```

若新增 demo 用例需单独的运行方式，说明是否已被上面命令收集，避免把未执行的用例计入通过数。
