# 第一阶段：双环境跑通

状态：待审批。日期：2026-10-30。

## 目标

让 EffGen 在官方平台和真实浏览器中各完成一个任务。两边共用决策循环、工具定义和日志结构，通过不同后端获取观察、执行动作。验收要能看到实际操作及其结果，工程要能重新安装运行。

## 实现方式

沿用 RoadMap 的生成器方案，在 EffGen 已有循环的工具执行处增加交互接口：网页动作交给环境后暂停，收到新观察再原地继续；内部记录、读取证据等工具直接执行。

官方端每次 `step()` 推进生成器，得到一个动作后返回平台。下一次 `step()` 把观察送回同一生成器。真实端也驱动同一生成器，由本地浏览器执行动作并立即返回观察。第一阶段两端均串行，后续真实端可让不同任务分支各持有独立循环和 Tab。

比较过两种替代方式：每步重新运行 Agent 会改变连续执行语义；后台线程等待浏览器反馈则增加任务上下文、超时与清理负担。因此优先改现有循环，不另写一套 Agent。

## 本阶段交付

1. **可复现工程。** Python 3.12，项目根目录建立 Git 仓库并创建 GitHub 私有仓库，保留现有文档。新建 harness、配置、测试和运行说明；凭据、浏览器资料及运行产物不提交。
2. **EffGen 接入。** 固定1.3.0源码提交，补充可暂停的工具执行接口；原有普通工具执行方式继续可用。明确配置单 Agent、文本 ReAct、任务预算和上下文预算，关闭不适用的自动探测、多模型调用与自动工具 fallback。
3. **官方适配。** 使用已下载的新版 SDK；模型调用走 `third_party_agent.model.generate(messages)`；只返回平台允许的单动作，按当前 AX 编号检查目标。支持新字段缺失时继续使用 AX。
4. **真实浏览器。** 分别试接 Playwright 和 browser-use，同一页面任务、同一模型、同一工具定义。browser-use 只复用浏览器操作与观察能力，不启动它自己的规划 Agent。初始默认后端为 Playwright；browser-use 是否保留为完整后端，以接入试验结果决定。
5. **事实与日志。** 保存任务、观察、动作、反馈、模型调用和终止原因。截图可按任务要求保存，与当时的页面和观察对应。
6. **运行验收。** 离线验证通过后，真实浏览器完成一个不提交业务数据的任务；官方平台至少一个任务获得有效评分并通过。保存运行命令、版本、证据和结果。

## 观察和工具

观察保留任务 ID、页面 ID、观察 ID、URL、AX 文本、当前有效元素、上一个动作的反馈，以及可选截图、HTML、DOM。两端使用同样的“页面＋观察版本＋元素编号”语义，不要求同一页面在两个环境中生成相同数字。

第一阶段只让模型读取任务、当前 AX、近期行动与预算；HTML、DOM 原件按需保存，暂不全量加入提示词。截图先用于证据，不配置额外视觉模型。

共用网页动作包括点击、输入、按键、滚动、导航、前进和后退。每次有效动作都会等待新观察，即使动作没有跳转页面。输入语义按官方接口处理，不能把追加与覆盖混同。真实端通过受控浏览器观察生成定位表，编号随观察失效。

完成与失败要区分：Agent 请求结束时输出说明，外围检查必要证据和格式，官方判分结果另存。框架异常、超时或结果不明不写成“任务完成”。

## 运行与预算

官方端受平台任务截止时间约束，所有模型调用、资料下载与本地计算均计入预算。不新增平台步数限制；EffGen 默认10次迭代必须显式处理，避免提前结束正常任务。

本地默认输入预算设为约24K token，总上下文规划为32K，作为工程配置而非模型官方规格。优先使用已核实的 tokenizer；无法精确计数时明确标为估算。超过预算保留任务条件、当前观察与待确认结果，压缩旧过程；当前观察本身过大时停止并报告，不能悄悄截断目标元素。后续观察筛选另行实验。

真实端从本地 env 读取模型地址和密钥，仅使用比赛统一模型。主线程先确认实际服务配置与模型身份；未知配置不猜测。请求只发送任务与页面所需内容，密钥和平台账号不进入提示词或日志。

第一阶段提供最小的暂停／继续入口：执行中可手动暂停，确认没有在途动作后交给用户；继续时重新观察并使旧编号失效。自动识别登录、验证和完整恢复策略属于第二阶段。
