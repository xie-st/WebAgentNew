# 第二阶段测试环境与任务

状态：待审批。测试用于确认能力是否按设计运行，不作机制优劣结论。

## 环境选择

本地采用一个轻量、仅绑定 localhost 的动态网页应用，复用项目已有 Web 依赖或 Python 标准库，不另部署整套 WebArena。官方平台已提供论坛、电商及判分；本地应用主要补足接管、并行、长任务和故障注入。

测试必须用实际渲染网页与真实按钮／表单，不以 JSON 状态机冒充浏览器。现有 fake_backend 继续承担协议、调度和时间测试；网页端到端另列。

本地应用提供商品／帖子列表、搜索、分页、详情、编辑草稿、保存／取消、登录遮罩和验证提示。用 SQLite 或等价持久存储保证多 Tab 看到同一状态；不同运行使用不同副本。

测试准备器负责初始化和故障注入，判定器负责读取隐藏状态；Agent 只能拿任务和正常网页观察。测试接口不注册进 Agent 工具，也不把预期答案、seed 对应答案或内部表读入提示词。

## 清单格式

`cases/*.yaml` 每项声明 case_id、任务模板、数据生成器、公开任务参数、setup、完成条件、故障计划、重置方式、支持模式和预算。隐藏判定参数与 Agent 可见参数分开读取。

首次固定 seeds=101、202、303用于功能验证；另预留404、505作第三阶段回归，不在本阶段用于调参。种子改变对象名称、数值、顺序、编号与布局。任务本质与判定条件不变，运行产物记录 case_version、seed、代码与配置版本。

## 本地任务

| ID | 任务 | 检验能力 | 外部判定 |
| --- | --- | --- | --- |
| L01 | 找出满足多项条件的对象，打开详情，跨页填写草稿并取消 | 关键值保存、同一对象一致性 | 对象、内容、截图正确；无提交 |
| L02 | 搜集分页中满足条件的5个不同对象，逐个核对，最后报告 | 去重、缺口、长列表 | 完整集合及证据；不能用访问次数凑数量 |
| L03 | 处理20条不同帖子：判断相关性／倾向，写含文字与表情的草稿，截图、取消 | 长任务账本与证据 | 每条编辑、截图、取消记录齐全；0次发送 |
| L04 | 修改简介并保存，第一次保存已生效但反馈延迟 | 副作用结果不明 | 最终内容正确且只保存一次；先取证再决定重试 |
| L05 | 第二个子目标失败，第一与第三个独立目标已完成 | 依赖闭包恢复 | 不重复第一／第三目标；只修复受影响链 |
| L06 | 编辑中出现登录／验证遮罩，由用户完成后继续 | 自动暂停与接管 | 交接后无 Agent 动作；继续重观测，草稿状态核对正确 |
| L07 | 用户主动暂停后改动页面，恢复原任务 | 旧动作撤销与状态更新 | 不消费旧提案、不用旧编号；以新观察继续 |
| L08 | 多个独立页面各等待一段响应后给出信息，合并结果 | 实际等待重叠、容量与排队 | 分别验证容量2和4；各页结果来自真实操作，时间线存在重叠；更多就绪节点排队且不遗漏 |
| L09 | 两个分支需要修改同一购物车对象，再汇总 | 写冲突协调 | 写动作不重叠，输入值基于有效版本，无丢更新 |
| L10 | 共享站点触发一次冷却，后续正常 | 全局限流与退避 | 两分支共同等待，未在冷却中继续发操作 |
| L11 | 分支运行中发现条件变化，修订任务图 | 旧结果处理、依赖调整 | 旧版本结果留档；不覆盖新计划；无效后继不执行 |
| L12 | 重复标签、隐藏按钮、目标不在筛选候选中 | DOM／AX 映射与回退 | 只用当前合法编号；扩大范围／AX 回退可见 |
| L13 | 长历史中有关键对象值，折叠后又发生证据冲突 | 历史管理、重新展开 | 原值和证据可查；撤回错误确认；原始日志不变 |
| L14 | 加载一条批准经验并执行有界组合，另放一条未批准经验 | 经验格式与执行约束 | 只用批准版本；每个网页原语有独立反馈 |

L03 网站的发送按钮实际记录提交计数，判定器检查零提交。任务中的“不发送”进入执行约束；不能仅依靠最后一次截图判断未发送。快捷键提交也计入。测试故障不得主动制造 Agent 未执行的发送。

## 故障计划

故障由测试准备器在指定事件后触发，不由 Agent 调用：控件暂时缺失、编号重排、重复按钮、慢响应、保存后反馈丢失、登录失效、验证遮罩、草稿丢失、共享对象被修改、冷却提示和 Tab 关闭。

每次只触发清单指定故障，记录触发事件与真值。验收时对照 Agent 的检测与恢复记录，不把测试器知道的原因直接注入 Agent。瞬时失败、结果不明和真实条件变化分别测试。

## 预算与运行方式

本地功能验证默认600秒执行预算，L03 默认1800秒；人工接管另列。官方任务沿用平台截止时间，不受本地配置延长。模型参数遵守实际接口，推理强度不在本阶段比较。

调度单元测试使用假时钟和可控延迟，不实际等待长时间；本地端到端使用真实浏览器和统一模型。L08 的实现正确性用时间线证明重叠即可，阶段二不要求达到某个加速比；第三阶段再做同条件串并行统计。

L08使用显式并行配置`max_active_branches=2`与`4`，每种分别安排N个与N+1个独立节点。用足够长的可控网页等待验证对应容量能够实际启用，N+1场景验证排队、槽位释放与最终汇总；不通过提高模型并发或取消站点限流实现。另以同一任务图跑串行路径，确认结果与证据归属一致。容量非法或并行模式未配置容量时，在启动浏览器和模型之前拒绝运行。

配置组合控制数量：基础配置跑全套，摘要／差分／折叠／筛选分别开启时只跑相关用例，最后增加一次组合兼容性检查。不能从开关冒烟测试推导性能收益。运行清单区分单元、假模型集成、真实模型本地网页和真实站点，结果不混合成一个通过率。

## 官方调测

主线程实施时读取当时任务清单并冻结版本。仅运行本队账号，最多一个在途任务，按平台支持方式顺序提交。任务文字原样保留，流程不按题号写死。

第二阶段在基础配置下运行当时可用的各网站批次一次，保留全部成绩、失败、未评分和取消项；本阶段要求连接与任务执行、日志关联正确，不以调测100%作为能力模块全部通过的前提。错误属于接入还是决策另行归类，后续优化实验报用户批准。

## 真实网站任务

采用赛方提供的小红书案例作为本阶段真实联调用例，不在此阶段扩展到其他平台。由用户接管完成登录和验证。任务文件提供关键词、至少20条、评价范围、评论内容要求和禁止发送；网站入口与当时可访问状态在运行报告记录。

每条帖子记录稳定链接或站内对象标识、可见相关内容、倾向判断依据、评论草稿、截图、取消后的观察及完成状态。不同帖子唯一计数，同帖重复访问、重复截图不增加数量。搜索没有穷尽性证据时不声称已搜索“所有”帖子；保留当前搜索范围与已完成数量。

后台限流、验证码或账号失效时共享暂停与接管。不能为了凑20条把未知倾向记为正向。截图保存时点必须在评论编辑后、取消前；取消后另留观察确认草稿已退出或清除。

此用例不发送评论，也不把帖子内容传给未批准的外部服务。现场查验由主线程和用户检查20组证据。无法运行或不足20条则真实任务记未完成，不能用本地L03替代；恢复后可从已核实数量续做。

## 输出与冻结

每次运行保存 manifest、原任务、配置、代码／SDK版本、种子、事件、状态修订、截图引用、判定结果及调用成本。失败原因分环境、协议、决策、恢复、接管和预算，未知保留未知。

进入第三阶段时冻结任务清单与基线配置，归档已知问题。后续任何任务、布局、种子、模型服务或预算变化都产生新版本；不可把不同版本直接汇总比较。
