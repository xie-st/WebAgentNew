## 1. 状态与计划

第一版只维护一个任务状态对象，由根协调器统一写入：

项目内部业务完成状态由TaskState统一记录，核验依据来自页面与证据；AgentThread继续保存执行轨迹，EvidenceStore保存原始证据，三者通过ID关联。不要把账本复制进LongTermMemory作为另一份可独立更新的完成状态，也不要为复用MemoryEntry而把整个TaskState塞进通用文本记忆条目。

| 层次 | 结构与职责 |
| --- | --- |
| 内存 | `TaskState`保存任务原文、revision、plan_version，以及按ID索引的goals、facts、plan和未确认副作用pending_effects；依赖直接保存在记录的ID列表中，按需遍历 |
| 持久化 | `runtime/runs/<root_run_id>/state/state.json`保存完整状态；先写完并刷盘临时文件，再原子替换旧快照；保存失败不提交候选内存状态，也不继续执行依赖该状态的动作 |
| 日志与原件 | 沿用第一阶段事件日志、Observation与EvidenceStore；账本只保存来源、引用和已有哈希，不重复存截图或动作全过程 |

分支提交带base_revision、plan_version和来源分支的更新请求，不能直接改共享字典或文件。根协调器串行检查，在候选状态中增加revision并保存，成功后替换内存状态；旧请求返回相关当前状态，重新检查后再提交。模型调用和浏览器等待不占状态更新锁。保留这个轻量版本检查，用来拒绝异步返回的旧结果，不实现多写入者事务或通用补丁重放框架。

快照是重启恢复依据，事件日志用于诊断，不靠日志重建状态，也不保证二者同时提交。先保存证据再提交引用；有副作用的动作发出前必须把action_id、目标、对象和待确认状态保存到pending_effects，保存失败则不发动作。反馈确认后更新；重启时残留记录一律先核实，不能自动重发。

主要记录：

| 类型 | 必需信息 |
| --- | --- |
| `Goal` | id、要求、验收条件、依赖目标、对象范围、状态、支持证据 |
| `Fact` | id、对象、字段／命题、值、observed/inferred、来源、有效性、修订号 |
| `PlanNode` | id、目标、依赖、输入事实、对象范围、资源声明、状态与计划版本 |

证据引用沿用已有ID、任务／分支归属和文件元数据；动作尝试直接关联Session及事件中的action_id。未完成条件和下一步所需信息保存在Goal中，不另建Gap实体。Goal状态为pending/running/awaiting_verification/verified/blocked/invalidated/cancelled；动作反馈沿用第一阶段含义，不把observed当verified。

计划由 EffGen 提出，程序检查 DAG 无环、依赖存在、对象范围和完成条件未丢失。保留用户原始任务，修订计划不能删除尚未满足的用户要求；无法完成则标 blocked 或 incomplete。模型不能自行提高已验证数量、删除失败样本或改变验收标准来“完成”任务。

状态更新采用上述版本检查，不覆盖未经重新核对的新值。已确认事实遇到相反证据时更新有效性并保留新旧来源；观测不到不是相反证据。推断允许被修正，但不能因置信度高直接变成观测事实。

给 EffGen 的状态工具至少提供 `state_read`、`state_update`、`plan_update`。程序检查证据存在、哈希、任务归属和引用关系；业务语义由后述核验判断。工具成功仅代表更新已记录。

## 2. 核验

`VerificationRequest` 包含目标、条件、待核验对象、证据范围和触发节点。`VerificationResult` 包含 pass/fail/unknown、条件逐项结果、证据、方法、调用量和原因。只有目标全部条件有 pass 才能 verified。

支持两类检查：

- 确定性检查：当前可见字段值、页面文本、URL、截图存在与归属等，基于正常浏览器观察，不读目标业务数据库或私有 API。
- 语义检查：相关性、评价倾向、内容是否满足要求，使用同一统一模型；输出结论和引用。模型无法判断时返回 unknown，不能强制二选一。

默认在业务写入后的可观察反馈、子目标结束、任务结束和结果不明时检查。只读导航不逐步另调核验模型。新观察已足以确定条件时直接更新，不重复抓取页面或下载同一原件。

语义调用可与原决策同轮生成候选判断，但必须基于当前已有证据，不能提前确认即将执行的动作。需要独立核验时所有调用进同一预算。截图保存成功只能确认截图条件，不能单凭此确认截图内文字满足任务。

官方模式保持 step 单动作。需要进一步取证时由 EffGen 在后续 step 正常操作，不在核验器内创建浏览器、注入脚本或直连网站。最终成绩仍以官方判分为准，内部 verified 单独记录。

在生成器返回最终 AgentResponse、Session.finish 之前增加完成检查入口：逐项核对根任务要求。未满足时把缺口交回同一 EffGen 循环继续行动，不能先关闭生成器再假称继续原循环；无法继续则诚实结束为 incomplete／blocked。检查需要新页面证据时仍由正常动作取得，不能在 finish 检查中隐式操作网页。

## 3. 恢复与停滞

对每次新反馈先记录动作结果及待确认副作用，再检查相关目标。分类为 protocol、transient、unknown_effect、condition_failed、no_progress、authentication、user_pause。分类可以有证据不足的 unknown，不将所有问题自动归为网络故障。

恢复流程：暂停受影响分支→找最早有冲突证据的动作或事实→计算依赖闭包→将受影响 verified 标 invalidated／awaiting_verification→保留其他确认结果→交 EffGen 提出下一步→正常执行与核验。

“回退”先指计划和完成判断的修正，不自动在网站上撤销业务数据。任何补偿动作仍经 Agent、网页工具和核验执行。unknown_effect 先取证；查不到结果时保留未知并请求用户决定，不盲目重发帖子、评论、订单或保存。

对纯只读、可重复的瞬时失败，可在剩余预算内重试，默认最多2次，间隔1秒、2秒；等待也计入运行时长。服务端 Retry-After 优先。频率限制由站点级调度器统一处理，不能与这里的重试叠加成双重重试链。

停滞初始窗口为6个有反馈的网页动作，至少两次相同状态重现，且没有新增相关证据或减少当前缺口时，生成诊断候选。动作相同或页面相同单独不能触发失败；翻页找新对象仍算进展。恢复提示限于当前目标、证据冲突和一项下一步调整，反思记录不超过最近3条，原始记录另存。这些是初始参数，第三阶段再比较。

恢复超过每目标2轮或全任务5轮后标 blocked，交用户；不无限重规划直到 deadline。预算耗尽、取消和失败分类分别保留。

## 4. 接管与恢复执行

增加根任务控制状态：running→pause_requested→draining→user_control→refreshing→running；另有 cancelled/blocked。这是分支控制层，不把 Session 原状态枚举随意改义。

暂停请求一到就关闭所有分支发新动作的门。未消费提案作废；在途模型调用可结束，但返回提案按控制版本丢弃，调用成本仍记入。浏览器动作排空；超时则记 unknown，确认后才提示接管。模型调用或点击尚在执行时不能声称浏览器已完全交出。

检测登录、验证时使用当前 AX、页面提示和动作反馈，生成接管原因；不自动填写账号、解验证码或调用密码管理器。用户主动暂停无须模型确认。CLI／控制面提供明确的继续与取消操作，默认等待用户确认继续，不猜测“过了若干秒即登录完成”。

继续后重观测受影响 Tab，增加 control_epoch 和 page_epoch，旧元素与动作失效；检查账号、页面、草稿等受影响事实。纯证据保存不算网页动作。旧生成器如果正停在一个已撤销提案处，须明确返回“未执行，因接管作废”的工具结果并送入新观察，不能把用户操作伪装成该动作执行成功。在交接驱动上复用或扩展显式恢复接口（如 `resume_after_takeover`），并测试在同一循环恢复；不要直接改 driver 私有字段。

本阶段优先保证进程内暂停恢复。进程重启只能从持久账本重新开始一个有标识的执行分支并重新观察，不声称 Python 生成器栈已恢复，也不重放未知副作用动作。

## 5. 分支与浏览器调度

保持官方路径单 Session／单循环。F批先用小型适配验证检查原生WorkflowDAG：节点能否通过已交接的交互驱动交出动作、接回观察，能否保持页面归属、全局暂停、动态计划失效与根预算；原生run／run_async节点接口及checkpoint不直接等同于浏览器接管或生成器恢复。验证写入F批报告，适用部分复用；为适配而改动更多时保留轻量TaskCoordinator，只实现原生机制不能满足的协调职责，不额外维护第二份计划。

根EffGen通过`plan_update`生成或修订任务图；每个就绪节点使用独立EffGenLoopDriver、Session和Tab。只保留一条明确的任务调度路径，关闭原生自动sub_agents；不能同时让工作流和项目协调器各自创建、重试或恢复同一节点。

子分支有 root_run_id、branch_id、独立合法 run_id。证据目录分开写，根事件索引关联它们；同一 EvidenceStore／JSONL 文件不能由多个分支无锁写入。时间、费用、模型调用在根层累计，包括规划、语义核验、失败重试和未采用结果。

子分支截止时间不得晚于根任务截止时间。模型调用前原子领取根预算，按唯一调用ID计数，前置事件和完成事件不重复计为两次调用。端到端时间按根任务起止计算，不能将分支耗时相加当总耗时；人工时间用全局接管区间计算，不重复扣除各分支的相同暂停。

新增真实端 `MultiPageBackend`：打开、关闭、切换／观察指定页；页内动作仍是原 WebAction。Tab 管理用单独的 BrowserCommand，不把新操作偷偷塞进官方 action 字符串。工具注册只暴露当前后端允许的工具；官方配置下模型看不到 Tab 管理工具，也不能因输出这类命令获得执行。

线程与页面规则：一个生成器同时只由一个所有者推进；每个 Tab 一条动作队列。浏览器 API 由单一所有者调度，使用选定后端支持的异步等待来重叠不同页的工作；不能把同步 Page 对象交给不同线程。全局焦点、剪贴板、桌面截图等操作占全局锁。可以先串行模型调用、重叠网页等待，不能因浏览器并行默认增加模型并发；真实模型并发初始为1。

调度前检查：依赖满足、输入事实有效、计划版本一致、目标未被其他分支领取、资源可用、站点节奏允许、全局未暂停、预算充足。领取与状态更新原子完成。

容量与速率分别配置：

| 项目 | 规则 |
| --- | --- |
| 计划节点 | 不受执行容量限制；未就绪或暂时不能执行的节点留在队列 |
| 活跃分支 | 默认serial，容量为1；parallel下`max_active_branches`默认2，允许配置其他正整数，支持大于2 |
| 浏览器资源 | 启动分支前取得可用Tab及所需资源；达到配置容量或后端资源容量时排队；资源创建失败返回明确错误，不继续增开 |
| 页内动作 | 每Tab最多1个在途动作；已在等待网页反馈的分支仍占活跃槽，不能在其页上偷开下一动作 |
| 模型调用 | 初始并发1，与活跃分支容量分开；等待模型决策的分支不发新动作，其他分支可正常等待网页反馈或执行已有合法提案；不持有状态更新锁 |
| 站点节奏 | 所有分支共享站点限流和退避，不随分支容量成倍增加 |

运行前校验并记录容量；超过容量的任务排队，不丢弃。已满足条件的节点按就绪顺序调度，资源冲突节点可跳过但保留原排队次序。单元与本地浏览器验证覆盖容量2和4，以及就绪任务多于容量的情况。容量不是性能结论；第三阶段再比较不同容量的完成率、耗时和成本。

资源声明至少覆盖 Tab、账号、对象和共享写目标。写冲突串行；只读可共享。多资源按固定顺序申请，等锁时不持有部分锁；持有共享状态不明的写操作资源时不得超时自动释放再让下一分支写。超时、取消和计划作废均先排空／标记未知，再释放资源。

计划修订使相关就绪任务作废、运行任务停止再发新动作。在途结果归入旧版本审计，重新核验后可显式复用，不能直接提交新账本。取消一个节点还应阻止依赖它的节点进入运行。

同一站点的所有分支共享容量1的令牌桶，初始1次页面操作／秒，与分支容量分开配置。等待使用可取消定时器，不持有模型调用槽。遇429／Retry-After或页面冷却提示时所有相关分支共享退避；无 Retry-After 时默认5、10、20秒退避，最多3轮，仍受总预算约束。真实站点规则更严时采用更严配置。暂停、取消时调度等待立即可唤醒。

## 6. 上下文与观察

先确认第一阶段实际输入链路中AgentThread、ContextBudget／CompactionPolicy、ContextPacker及模型适配器的调用顺序。EffGen继续维护轨迹与历史压缩，项目侧提供必要账本和观察视图，并校验最终token、字节和消息限制；共享有效输入token预算，不允许一边先压缩，另一边再独立截断同一历史。检查对象始终是最终发给模型的messages／prompt，不能只生成PackedContext文件而实际发送另一份输入。

优先使用AgentThread的结构化步骤、原生消息／文本渲染和CompactionPolicy扩展点。项目`context/`只负责必要区装配、项目历史选项和现有链路适配，不另写完整context_renderer替代原生prompt构造，不复制thread作为第二套历史。需要新钩子时按前述补丁范围规则处理；普通Agent.run行为保持不变。禁止按文本分隔符猜测并截掉ReAct历史。

必要区包含任务原文、当前页及元素编号、相关对象值、活动目标、未确认副作用和恢复／接管状态。可变区包含旧观察和完成过程。首先缩减可变区；必要区放不下则明确超限，不截断后悄悄发送。计数来源明确标记，模型返回 usage 与输入估算分列。

将项目必要区纳入选用策略的保护范围，不能仅假设原生默认保护集已覆盖账本。摘要、差分与折叠作为同一入口中的视图／策略组合，每份旧步骤只形成一份最终表示；多开关时明确应用顺序，不能先丢弃再要求还原。原始观察与事件留在EvidenceStore和日志，不随thread的压缩而覆盖。

运行摘要分别写出跨任务记忆设置、原生context_budget／compaction及项目开关。项目历史选项全关闭仍可触发原生预算压缩；基线要验证其实际行为。默认原生策略不新增模型调用；如后续获准启用模型摘要，所有调用必须先经过根预算、deadline及官方任务上下文检查，不能只依赖原生用量日志认为已受预算约束。未选用的原生可选功能不要求新增支持。

新增选项，默认都关闭：

| 配置项 | 契约 |
| --- | --- |
| `context.step_summary` | 同轮短摘要，最多约200字，基于当前／过去事实；未来动作意图另列，不能写成已完成 |
| `context.history_diff` | 只编码同页旧观察差分，记录 base_ref、target_ref 与哈希；跨页或无法还原则保存全量历史；当前页完整 |
| `context.fold_completed` | 折叠已确认子目标的叙述；保留输出值、证据、依赖与恢复锚点，可重新展开；被撤回确认的目标重新展开 |
| `observation.task_filter` | 固定评分程序使用关键词／权重选候选；不执行模型生成的任意代码 |
| `experience.enabled` | 仅加载本地人工批准经验，默认空库 |

同轮摘要和状态候选通过网页工具的可选 `context_update` 字段生成，由唯一工具 schema 注册；进入 WebAction 之前取出并验证，绝不发给官方协议。旧模型输出不含此字段仍可用。验证失败不提交该增量，回给 Agent 明确错误；不因摘要失败自动补调一个模型。单独 state_update 仍可用，消耗正常决策调用，不声称免费。

DOM／AX 候选处理先去脚本、样式、注释和不可交互内容，保留完成判断所需正文与数值。默认 Top-N=40，可扩大一次或恢复完整 AX；阈值和候选数单独配置。官方 DOM 到 AX 无可靠映射时退回 AX 候选筛选；重复标签不可凭文本硬匹配。保存输入观察、参数、候选与回退原因；不伪造“已复现 Prune4Web 全方法”。

## 7. 经验和有限组合

先核对交接版本的工具schema、注册、提示词注入和分发路径；文本经验进入现有提示词装配，有限组合逐步调用已有网页工具与核验入口。沿用BaseTool／harness已有注册方式，不建立独立skill执行器或另一份工具注册表。若最终版本出现可用的原生skill接口，先确认其批准、前置条件和逐步交接约束再复用，不按名称直接接入。

经验格式含 id、版本、用途、前置条件、步骤／文本指导、核验条件、来源、适用后端和批准状态。仅加载 allowlist 中的批准版本，页面内容不能变成新 skill 或修改其批准状态。

有限组合只允许已注册网页原语、条件检查和有界循环，最多10个网页原语；每个都经过当前观察定位、调度、限流和反馈。默认遇条件不符即退出交回 EffGen，不自动修补或执行任意 Python／JS。官方端每个原语仍占一个 step；不增加后台操作。

阶段二只验收读取和执行接口，不建立自动学习流水线。示例经验使用本地任务验证通用的“修改字段后核对”，不能包含官方题目名称、固定答案或帖子链接。

## 8. 配置、日志与交付

增加显式阶段二配置组，默认兼容现有配置，并映射到已选用的EffGen原生配置，不新增含义相同却各自生效的开关。功能参数与实际原生策略均写入运行摘要，不能在代码中按 task_id／网站题目切换。官方 profile 强制浏览器并发1、模型并发1、关闭 Tab 工具与人工延长 deadline。

事件增加 state_revision、goal_id、branch_id、plan_version、control_epoch、verification、recovery、lock_wait、rate_wait、handoff 及 context_pack 等信息。保持第一阶段事件可读取。并行运行至少能还原每个模型调用、动作、等待与用户接管的起止；根总量不能只统计成功分支。

按 [测试任务](04_测试环境与任务.md) 实现统一 runner，支持 fake-clock 单元测试、本地网站端到端和人工真实运行。worker 交付代码、针对性测试、命令和证据，不跑公开网站与官方任务。主线程只执行用户要求的复验范围；如最新指令要求 worker 返回后停止，不自行复跑或续派。

CLI 增加 `suite validate --manifest <文件>`、`suite reset --case <ID> --seed <种子>` 和 `suite run --manifest <文件> --execution fake|local|official|real-site --mode serial|parallel`。默认 execution=fake、mode=serial；真实模式须显式指定且缺凭据时失败，不自动降为假模型。run支持按case与seed筛选，结果写manifest与报告；validate不运行模型、不登录、不提交任务。官方profile拒绝parallel。

每批报告对应 [验收编号](03_验收要求.md)，记录通过、失败、未执行及原因。任何“全部通过”必须指明范围，不用假模型结果替代真实模型或网页结果。
